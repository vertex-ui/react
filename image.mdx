# Image

<ComponentStatus status="stable" version="1.0.0" aria="WAI-ARIA Image" />

## Before You Start

Image represents a standard HTML `<img>` with added JavaScript state management. It renders a wrapper `<div>` that contains both the main image and an optional fallback image, swapping their opacity based on load events. The Quick Start example below will render an image that defaults to native lazy loading.

<Callout type="tip" title="New to Luxis UI?">
  The `Image` component wrapper defaults to `width: 100%` and `height: 100%`. Ensure you place it inside a sized container.
</Callout>

### EagerLoad

By default, images are lazy-loaded. Use the `priority` prop to eager load images that are "above the fold" to improve LCP (Largest Contentful Paint).

<!--
EXAMPLE: EagerLoad
PURPOSE: Disabling lazy loading for critical images
OUTPUT: An image that loads immediately with the document
USE WHEN: Rendering hero images at the top of the viewport
SOURCE: app/storybook/src/stories/Image.stories.ts -> EagerLoad
-->
```tsx
import { Image } from '@luxis-ui/core';

export default function EagerLoadExample() {
  return (
    <div style={{ width: 400, height: 300 }}>
      <Image
        src="https://images.unsplash.com/photo-1506744038136-46273834b3fb?w=400"
        alt="Hero image"
        priority
        fetchPriority="high"
      />
    </div>
  );
}
```

This applies `loading="eager"` and `fetchPriority="high"` to the underlying DOM node.

### Controlled Image

When to use: When a parent component needs to read or drive the state based on image load events.

<Callout type="info" title="Controlled vs Uncontrolled">
  Image manages its own loaded/error state internally. You can listen to these events using `onLoad` and `onError` via standard HTML props, which are forwarded to the underlying image.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: Responding to image load states externally
OUTPUT: Text that updates when the image finishes loading
USE WHEN: Triggering layout recalculations or removing loaders
SOURCE: Derived from Image.tsx
-->
```tsx
import { useState } from 'react';
import { Image } from '@luxis-ui/core';

export default function ControlledExample() {
  const [status, setStatus] = useState('Loading...');

  return (
    <div style={{ width: 400 }}>
      <p style={{ marginBottom: 8, fontWeight: 'bold' }}>Status: {status}</p>
      <div style={{ width: 400, height: 300, background: '#f5f5f5' }}>
        <Image
          src="https://images.unsplash.com/photo-1506744038136-46273834b3fb?w=600"
          alt="Controlled example"
          onLoad={() => setStatus('Loaded successfully!')}
          onError={() => setStatus('Failed to load')}
        />
      </div>
    </div>
  );
}
```

### Image Props

| Prop | Type | Default | Required | Description |
|------|------|---------|----------|-------------|
| `alt` | `string` | - | true | Alternate text for the image |
| `src` | `string` | - | true | Source URL of the image |

### HTML Native Props

Image accepts standard `React.ImgHTMLAttributes`, forwarding them either to the wrapper or the underlying image depending on the prop type. Events like `onLoad` and `onError` are forwarded to the underlying image.

| Prop | Description | Example Value |
|------|-------------|---------------|
| `onLoad` | Load success callback | `(e) => handleLoad(e)` |
| `onError` | Load failure callback | `(e) => handleError(e)` |

## Image Accessibility Guide

Image enforces standard `img` accessibility patterns.

### Screen Reader Behavior

The screen reader will read the `alt` text attribute of the main image. The `fallback` image automatically receives an `alt` attribute of `"{alt} loading image"` to provide context while loading, but it is visually and programmatically hidden once the main image loads successfully.

### Accessibility Checklist

- [ ] Always provide descriptive `alt` text.
- [ ] If an image is purely decorative, provide an empty string `alt=""`. (Note: TypeScript might require it, so be intentional).
- [ ] Do not include words like "image of" or "picture of" in the `alt` text.

## Troubleshooting Image

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Image overflows container | Container lacks `overflow: hidden` | Add `overflow: hidden` to parent if using `borderRadius` |
| Image looks stretched | Container lacks dimensions | Define width and height on the parent `<div>` |
| Fallback flashes on fast networks | Fallback is too heavy | Use tiny base64 strings or low-res JPEGs for fallbacks |
| Next.js Image throws errors | Forgetting `imageProps` | Pass `fill` or `width`/`height` inside `imageProps` |

### Frequently Asked Questions

**Q: Why do I need to wrap the Image component in a div to set its size?**
A: The Luxis UI Image component uses `width: 100%` and `height: 100%` internally along with absolute positioning to manage the crossfade between the fallback and main image. Setting fixed dimensions on a parent wrapper ensures both layers stack and size correctly.

**Q: Does it support `srcset`?**
A: Yes. You can pass `srcSet` and `sizes` via the `imageProps` object, which passes them down to the underlying `<img>` tag.


**Q: How do I handle lazy loading?**
A: Image uses the browser's native `loading="lazy"` by default. You do not need to configure anything unless you specifically want to disable it using `priority`.

**Q: Can I use this with SVG files?**
A: Yes, but for purely decorative UI icons, it is better to render SVGs directly as inline components to avoid network overhead.
