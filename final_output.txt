# Grid

<ComponentStatus status="stable" version="1.0.0" aria="N/A" />

Grid is a responsive 12-column layout system based on Flexbox. It helps you build complex structural layouts that adapt cleanly across different screen sizes.

<Callout type="info" title="Migrating from another library?">
  Luxis UI `Grid` is functionally equivalent to MUI's `<Grid>` and Radix UI's `<Grid>`. It uses the familiar `container` and `item` pattern.
</Callout>

## Before You Start

Grid operates on a 12-column grid system using CSS Flexbox. It requires two types of components: a wrapper with the `container` prop, and children with the `item` prop. The Quick Start example below will render three equally spaced columns.

<Callout type="tip" title="New to Luxis UI?">
  The spacing system uses units. A spacing of `2` typically equals `16px` (2 * 8px base unit).
</Callout>

## How to Use Grid in React

The minimum code to render a working Grid:

<!--
EXAMPLE: Basic Usage
PURPOSE: Minimum viable implementation of Grid
OUTPUT: A row of three equal-width columns
USE WHEN: Building a simple evenly distributed row
SOURCE: Derived from Grid.tsx defaults and simplest Story
-->
```tsx
import { Grid } from '@luxis-ui/core';

export default function Example() {
  return (
    <Grid container spacing={2}>
      <Grid item xs={4}>Column 1</Grid>
      <Grid item xs={4}>Column 2</Grid>
      <Grid item xs={4}>Column 3</Grid>
    </Grid>
  );
}
```

This creates a Flexbox container with a gap (spacing=2), containing three items that each take up 4 out of 12 columns (33.3%).

### Controlled Grid

When to use: When a parent component needs to read or drive the layout state.

<Callout type="info" title="Controlled vs Uncontrolled">
  Grid is entirely stateless and declarative. However, you can pass state variables to its layout props to dynamically change the grid structure based on user interactions.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: State-driven Grid layout
OUTPUT: A grid whose spacing changes via a button click
USE WHEN: Building customizable layout engines or responsive toggles
SOURCE: Derived from Grid.tsx
-->
```tsx
import { useState } from 'react';
import { Grid, Button } from '@luxis-ui/core';

export default function ControlledExample() {
  const [spacing, setSpacing] = useState<0 | 1 | 2 | 3 | 4>(2);

  return (
    <div>
      <button onClick={() => setSpacing(spacing === 4 ? 0 : (spacing + 1) as any)}>
        Toggle Spacing (Current: {spacing})
      </button>
      <div style={{ marginTop: '16px' }}>
        <Grid container spacing={spacing}>
          <Grid item xs={6}><div style={{ background: '#eee', padding: '16px' }}>Left</div></Grid>
          <Grid item xs={6}><div style={{ background: '#ddd', padding: '16px' }}>Right</div></Grid>
        </Grid>
      </div>
    </div>
  );
}
```

## Grid Best Practices

Use these practices to build maintainable, bug-free layouts.

<DoAndDont
  good={`// ✅ Use items directly inside containers
<Grid container>
  <Grid item xs={6}>Content</Grid>
</Grid>`}
  bad={`// ❌ Don't place non-item elements directly inside containers
<Grid container>
  <div>Content</div>
</Grid>`}
/>

<DoAndDont
  good={`// ✅ Define mobile (xs) layout first
<Grid item xs={12} md={6}>Content</Grid>`}
  bad={`// ❌ Don't skip defining a base layout
<Grid item md={6}>Content</Grid>`}
/>

<DoAndDont
  good={`// ✅ Use 'auto' for shrink-to-fit sizing
<Grid item xs="auto">Fixed width content</Grid>`}
  bad={`// ❌ Don't hardcode fixed widths on items
<Grid item style={{ width: '200px' }}>Content</Grid>`}
/>

<DoAndDont
  good={`// ✅ Wrap container around items
<Grid container spacing={2}>
  <Grid item xs={12}>...</Grid>
</Grid>`}
  bad={`// ❌ Don't combine container and item on the same node
<Grid container item xs={12}>...</Grid>`}
/>

## Grid Accessibility Guide

Grid relies entirely on Flexbox and standard `<div>` elements. It is structurally neutral.

### Screen Reader Behavior

Because Grid uses generic `<div>` tags, screen readers will interpret it purely as container elements without special semantic meaning. If the content of your grid represents a logical list or a specific landmark area, you should manually add semantic tags (like `<nav>`, `<ul>`, `<main>`) inside the grid items.

### Accessibility Checklist

- [ ] Do not rely solely on visual layout to convey meaningful order; ensure DOM order makes sense.
- [ ] Add semantic HTML tags inside grid items when grouping related content.
- [ ] Always verify with keyboard-only navigation before shipping

## Grid Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions like colors, spacing, and radius. Override them to restyle Grid without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-grid-spacing-unit` | `8px` | The base multiplier for all spacing props |

**Override globally:**
```css
:root {
  --lxs-grid-spacing-unit: 10px;
}
```

**Override for one section:**
```css
.my-custom-layout {
  --lxs-grid-spacing-unit: 4px;
}
```

**Override on one instance:**
```tsx
<Grid
  container
  style={{ '--lxs-grid-spacing-unit': '12px' } as React.CSSProperties}
>
  ...
</Grid>
```

## Troubleshooting Grid

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Items don't wrap correctly | Forgetting `<Grid container>` wrapper | `<Grid container><Grid item>...</Grid></Grid>` |
| Spacing creates horizontal scrollbar | Adding padding directly to the container | Use the `spacing` prop and `overflow: hidden` on parent if needed |
| Columns don't stack on mobile | Setting fixed `width` CSS | Use `xs={12}` on the Grid item |
| Nested grids act weirdly | Not using `item` and `container` together | `<Grid item xs={12} container spacing={2}>` |

### Frequently Asked Questions

**Q: Can a Grid be both a container and an item?**
A: Yes. You can pass both `container` and `item` props to nest grids. This is useful for grouping sub-layouts within a parent grid.

**Q: How do I remove the negative margins created by spacing?**
A: The Grid container uses negative margins to align items properly. If this causes horizontal scrolling on the root of your page, wrap the entire grid in a standard `<div>` with `overflow: hidden;` or ensure your `<body>` doesn't have `margin: 0;` conflicts.

**Q: Does Grid use CSS Grid under the hood?**
A: No. Despite the name, this component is built using CSS Flexbox for broader compatibility and predictable layout degradation. It behaves identically to the Material-UI grid system.


**Q: How do I make columns equal width?**
A: If you don't specify a breakpoint value (like `xs={4}`), passing just `xs` or `md` without a number will distribute the remaining space evenly among all items.

    { id: '2', title: 'New user joined', time: '10m ago', type: 'info' as const, read: false }

  const handleMarkAllAsRead = () => {
    setNotifs(notifs.map(n => ({ ...n, read: true })));

  const handleNotificationClick = (item: any) => {

      title="Alert Center"
      notifications={notifs}
      onMarkAllAsRead={handleMarkAllAsRead}
      onNotificationClick={handleNotificationClick}
    />
  );

## Header Accessibility Guide

Header renders a semantic `<header>` tag.

### Keyboard Shortcuts

| Key | Action |

| <KeyboardKey>Enter</KeyboardKey> | Opens dropdowns or triggers actions |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `aria-label` | `"Toggle sidebar"` | On the hamburger menu button |
| `aria-label` | `"Notifications"` | On the bell icon button |
| `aria-label` | `"User menu"` | On the user profile trigger |

### Screen Reader Behavior

Screen readers will announce the header region. The internal icon buttons have appropriate aria-labels so a user will hear "Toggle sidebar button", "Notifications button", etc. Unread notification counts are visually hidden but generally read out contextually if they receive focus or aria-live is implemented externally.

### Accessibility Checklist

- [ ] Provide a `title` or `logo` that helps identify the application.
- [ ] If using custom icons in `actions`, ensure they have `aria-label` properties.
- [ ] Always verify with keyboard-only navigation before shipping

**Q: How do I style the mobile sidebar toggle button?**
A: You can target it with the class `.lxs-header-toggle` in your custom CSS, or pass custom icons if supported by your application layout.

## Image Accessibility Guide

Image enforces standard `img` accessibility patterns.

### Screen Reader Behavior

The screen reader will read the `alt` text attribute of the main image. The `fallback` image automatically receives an `alt` attribute of `"{alt} loading image"` to provide context while loading, but it is visually and programmatically hidden once the main image loads successfully.

### Accessibility Checklist

- [ ] Always provide descriptive `alt` text.
- [ ] If an image is purely decorative, provide an empty string `alt=""`. (Note: TypeScript might require it, so be intentional).
- [ ] Do not include words like "image of" or "picture of" in the `alt` text.

## Troubleshooting Image

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Image overflows container | Container lacks `overflow: hidden` | Add `overflow: hidden` to parent if using `borderRadius` |
| Image looks stretched | Container lacks dimensions | Define width and height on the parent `<div>` |
| Fallback flashes on fast networks | Fallback is too heavy | Use tiny base64 strings or low-res JPEGs for fallbacks |
| Next.js Image throws errors | Forgetting `imageProps` | Pass `fill` or `width`/`height` inside `imageProps` |

### Frequently Asked Questions

**Q: Why do I need to wrap the Image component in a div to set its size?**
A: The Luxis UI Image component uses `width: 100%` and `height: 100%` internally along with absolute positioning to manage the crossfade between the fallback and main image. Setting fixed dimensions on a parent wrapper ensures both layers stack and size correctly.

**Q: Does it support `srcset`?**
A: Yes. You can pass `srcSet` and `sizes` via the `imageProps` object, which passes them down to the underlying `<img>` tag.


**Q: How do I handle lazy loading?**
A: Image uses the browser's native `loading="lazy"` by default. You do not need to configure anything unless you specifically want to disable it using `priority`.

**Q: Can I use this with SVG files?**
A: Yes, but for purely decorative UI icons, it is better to render SVGs directly as inline components to avoid network overhead.

# Input

<ComponentStatus status="stable" version="1.0.0" aria="WAI-ARIA Form Field" />

The Input component is a comprehensive wrapper around the native HTML `<input>` element. It abstracts away the complexity of wiring labels, error states, icons, and accessible descriptions, allowing you to build robust forms quickly.

<Callout type="info" title="Migrating from another library?">
  Luxis UI `Input` acts like Chakra UI's `FormControl` + `Input` combined, or MUI's `TextField`. You do not need separate components for labels or error messages.

## Before You Start

Input replaces the native `<input type="text">` (and similar types like email, number, password). It manages its own visual container to support icons and prefixes while maintaining native accessibility. The Quick Start example will produce a standard input field with a label and helper text.

<Callout type="tip" title="New to Luxis UI?">
  The `fullWidth` prop is very useful in forms to make the input span its container's entire width.
</Callout>

## Input Accessibility Guide

Input adheres to standard Form Field WAI-ARIA patterns and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Focuses the input element |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `aria-invalid` | `"true"` | When `error` prop is provided |
| `aria-describedby` | `"{id}"` | Automatically links to `helperText`, `error`, or `success` text nodes |
| `aria-hidden` | `"true"` | Placed on decorative icons, prefixes, and suffixes |
| `aria-label` | `"required"` | Placed on the visual red asterisk |

### Screen Reader Behavior

When focused, the screen reader announces the input type, the `label`, and any connected `aria-describedby` text (like error messages or helper text). If `error` is present, it will announce that the field is invalid. The character counter uses `aria-live="polite"` to announce updates. The clear button has an `aria-label` of "Clear input" but is purposely removed from the tab sequence (`tabIndex={-1}`) so users don't have to tab twice to get out of the field; it remains clickable.

### Accessibility Checklist

- [ ] Always provide a `label` (if visual label is omitted, ensure `aria-label` is passed via native props).
- [ ] Use `error` text to explain *why* validation failed, not just that it did.
- [ ] Ensure example text has sufficient color contrast if overriding the default.
- [ ] Always verify with keyboard-only navigation before shipping

## Troubleshooting Input

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Clear button doesn't empty field | Relying on `clearable` without state | Provide `value` and handle `onClear={() => setValue('')}` |
| Counter doesn't show | Passing `showCount` without limit | Must provide both `showCount` AND `maxLength={50}` |
| Width doesn't match container | Setting `style={{ width: '100%' }}` | Use the `fullWidth` prop |
| Prefix text is cut off | Trying to use `leftIcon` for text | Use the `prefix` prop for text, `leftIcon` for SVGs |

### Frequently Asked Questions

**Q: How do I make a textarea instead?**
A: Use the separate `<Textarea>` component, as `<Input>` is strictly for single-line text fields.

**Q: Why doesn't the clear button gain focus when I press Tab?**
A: By design, the clear button has `tabIndex={-1}`. This prevents users who are navigating a long form from having to press Tab twice to move to the next logical field. They can clear the input by selecting all and deleting, or clicking the button with a mouse.

**Q: Can I put a dropdown inside the input, like a country code selector?**
A: No, the `prefix` and `leftIcon` props are meant for static visual aids. For complex compound inputs, build a custom row using `<Flex>` wrapping an `<Autocomplete>` and an `<Input>`.


**Q: How do I get a reference to the actual input element?**
A: Pass a `ref` prop as you would with a standard input. The component uses `forwardRef` to pass it down directly to the native element.

## Link Accessibility Guide

Link follows the Link WAI-ARIA pattern and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Focuses the link |
| <KeyboardKey>Enter</KeyboardKey> | Activates the link and navigates to the destination |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `aria-disabled` | `"true"` | When `disabled` prop is true |
| `target` | `"_blank"` | When `external` prop is true |
| `rel` | `"noopener noreferrer"` | When `external` prop is true |

### Screen Reader Behavior

When a screen reader encounters a Link, it will announce it as a "link" along with the text content. If the `external` prop is used, it often announces that the link opens in a new window. If the `disabled` prop is set, the `href` attribute is removed, causing the screen reader to treat it as inert plain text, or announce it as a disabled element, preventing confusion.

### Accessibility Checklist

- [ ] Ensure link text clearly describes the destination (avoid "click here").
- [ ] Use the `external` prop when linking off-site.
- [ ] Do not use links for actions; use buttons instead.
- [ ] Always verify with keyboard-only navigation before shipping

## Link Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions like colors, spacing, and radius. Override them to restyle Link without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |

## Troubleshooting Link

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Next.js error: "Hydration failed" | `<Link><NextLink>Home</NextLink></Link>` | `<Link component={NextLink} href="/">Home</Link>` |
| Keyboard can still navigate | `<Link onClick={(e) => e.preventDefault()}>` | `<Link disabled>` |
| Open in new tab issues | `<Link target="_blank">` | `<Link external>` |
| Click event fires but changes URL | `<Link onClick={myAction} href="#">` | Use a `<Button>` instead |

<Callout type="warning" title="Next.js / SSR">
  When passing `NextLink` to the `component` prop, ensure you are using Next.js 13+. Earlier versions may require handling `passHref` and `legacyBehavior` wrappers differently.
</Callout>

### Frequently Asked Questions

**Q: Why doesn't my React Router link navigate without reloading?**
A: Make sure you are passing the router component via the `component` prop (e.g., `<Link component={RouterLink} ... />`) instead of just rendering a native anchor tag.

**Q: Can I put a Button inside a Link?**
A: No, nesting interactive elements is invalid HTML and causes accessibility issues. Use the `component` prop on the Button itself to make it act as a link if needed, or style the Link to look like a Button.

**Q: How do I change the link color?**
A: Use the `color` prop for predefined theme colors (e.g., `color="primary"`), or apply standard CSS classes.

**Q: Why is my disabled link still visible?**
A: The `disabled` prop removes interactivity and sets appropriate ARIA attributes, but it maintains visibility (often with reduced opacity) so users know the option exists.

## Menu Best Practices

Follow these guidelines to ensure your menus are intuitive and accessible.

<DoAndDont
  good={`// ✅ Group related actions with dividers

  { label: 'Copy' },

## Menu Accessibility Guide

Menu follows the Menu Button WAI-ARIA pattern and meets WCAG AA standards.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Focuses menu items |
| <KeyboardKey>Enter</KeyboardKey> | Activates item, toggles submenu, or opens ActionMenu |
| <KeyboardKey>Space</KeyboardKey> | Activates item, toggles submenu, or opens ActionMenu |
| <KeyboardKey>ArrowDown</KeyboardKey> | Opens submenu |
| <KeyboardKey>ArrowUp</KeyboardKey> | Closes submenu |
| <KeyboardKey>Escape</KeyboardKey> | Closes ActionMenu or responsive mobile menu |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"menu"` | Applied to the container |
| `role` | `"menuitem"` | Applied to individual items |
| `aria-haspopup` | `"menu"` | When an item has a submenu or on the ActionMenu trigger |
| `aria-expanded` | `boolean` | Indicates if a submenu or ActionMenu is open |
| `aria-disabled` | `"true"` | When an item or menu is disabled |

### Screen Reader Behavior

Screen readers will identify the `ActionMenu` trigger as a button with a menu popup. When opened, it will read the contents as a menu list. `MenuItem` components announce their label, state (e.g., active or disabled), and whether they contain a submenu (collapsible/expandable).

### Accessibility Checklist

- [ ] Ensure `triggerLabel` is meaningful if not using a custom trigger with text.
- [ ] Do not trap focus indefinitely within the menu.
- [ ] Use valid `aria-label` attributes if rendering icon-only custom triggers.
- [ ] Always verify with keyboard-only navigation before shipping

## Troubleshooting Menu

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Dropdown goes off-screen | `position="bottom-end"` near right edge | `position="bottom-start"` or adapt based on layout |
| Mobile menu doesn't appear | Missing `<meta name="viewport">` | Ensure standard responsive meta tag is present |
| ActionMenu won't close on click | Missing `onClick` in item | Ensure `onClick: () => {...}` is defined |
| Submenu icons don't align | Mixing items with/without icons | Pass an empty/transparent icon to align text |

### Frequently Asked Questions

**Q: How do I route to a new page using a MenuItem?**
A: Provide an `onClick` handler that calls your router's navigation method (e.g., `router.push('/page')`), or wrap the MenuItem text in a standard Link component if appropriate for your setup.

**Q: Can I keep the ActionMenu open after clicking an item?**
A: By default, `ActionMenu` closes when an item with an `onClick` handler is clicked. To prevent this, you would need to implement a fully custom trigger using the render function pattern and manage the `isOpen` state manually if necessary, though this goes against typical dropdown UX.

**Q: How do I change the width of the ActionMenu dropdown?**
A: Use standard CSS targeting the class passed to `className` on the `ActionMenu`, e.g., `.my-menu { width: 300px; }`.

**Q: Does Menu support dark mode?**
A: Yes. All Menu components listen for the `data-theme="dark"` attribute on the document root and adjust their colors, borders, and hover states automatically.
