  Luxis UI `Typography` is equivalent to MUI's `<Typography>`,

## Before You Start

Typography is the foundational building block for all text in your application.
It automatically maps the `variant` prop to the most appropriate semantic HTML element (e.g., `h1` variant renders an `<h1>`).
The Quick Start example below will produce standard paragraph text using the default `body1` variant.

<Callout type="tip" title="New to Luxis UI?">
  Check out our Getting Started guide to learn about our design principles and theme configuration.
</Callout>

## Typography Best Practices

Typography is the most used component in the system. Use it semantically and consistently.

<DoAndDont
  good={`// ✅ Use the 'as' prop to fix document outline issues
<Typography variant="h3" as="h2">Section Header</Typography>`}
  bad={`// ❌ Don't skip heading levels just because you like the size
<Typography variant="h5">Skipped from h2 to h5</Typography>`}
/>

<DoAndDont
  good={`// ✅ Use lineClamp for predictable card heights
<Typography variant="body2" lineClamp={3}>
  Very long description text...
</Typography>`}
  bad={`// ❌ Don't use truncate for large paragraphs
<Typography variant="body2" truncate>
  Very long description text that gets cut off immediately...
</Typography>`}
/>

<DoAndDont
  good={`// ✅ Use semantic colors for feedback
<Typography color="error">Invalid email address</Typography>`}
  bad={`// ❌ Don't hardcode hex values when a token exists
<Typography textColor="#ef4444">Invalid email address</Typography>`}
/>

<DoAndDont
  good={`// ✅ Use the label variant with htmlFor
<Typography variant="label" htmlFor="first-name">First Name</Typography>`}
  bad={`// ❌ Don't use a standard body variant for form labels
<Typography variant="body1">First Name</Typography>`}
/>

## Typography Accessibility Guide

Typography follows standard HTML patterns and meets WCAG AA text contrast requirements when using default tokens.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | No specific action. Typography elements are non-interactive unless wrapped in or rendered as links/buttons. |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | N/A | Typography relies on semantic HTML tags (`h1`-`h6`, `p`, etc.) rather than explicit ARIA roles. |

### Screen Reader Behavior

Because Typography automatically maps the `variant` prop to the correct semantic HTML tag (e.g., `<p>` for body copy, `<h1>` for page titles), screen readers will naturally interpret the document structure. Headings are critical for screen reader users to jump between sections of a page.

### Accessibility Checklist

- [ ] Ensure heading levels do not skip (e.g., don't jump from h2 to h4). Use the \`as\` prop to decouple visual size from semantic level if needed.
- [ ] Ensure custom \`textColor\` values meet WCAG 4.5:1 contrast ratios against their background.
- [ ] Use \`variant="label"\` and the \`htmlFor\` prop to properly link labels to form inputs.
- [ ] Avoid relying purely on color to convey meaning (e.g., error states).

## Typography Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Typography without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-text-h1-font-size` | `var(--lxs-font-size-4xl)` | Base size for h1 variant |
| `--lxs-text-h1-font-weight` | `var(--lxs-font-weight-extrabold)` | Base weight for h1 variant |
| `--lxs-text-body1-font-size` | `var(--lxs-font-size-base)` | Base size for body1 variant |
| `--lxs-text-secondary` | `#6b7280` | Muted color (used by caption and overline) |

**Override globally:**
```css
:root {
  --lxs-text-h1-font-size: 3rem;
}
```

**Override for one section:**
```css
.hero-section {
  --lxs-text-h1-font-size: 4.5rem;
}
```

**Override on one instance:**
```tsx
<Typography
  style={{ '--lxs-text-secondary': '#9ca3af' } as React.CSSProperties}
  variant="caption"
>
  Custom token color
</Typography>
```

## Troubleshooting Typography

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Screen reader says "heading level 5" but visually it's huge | \`variant="h1" as="h5"\` | \`variant="h1"\` or \`variant="h5" as="h1"\` (ensure semantics match layout hierarchy) |
| \`truncate\` doesn't work on multi-line text | Using \`truncate\` for paragraphs | Use \`lineClamp={3}\` instead |
| Semantic colors don't apply | Overriding with inline \`style={{ color: 'red' }}\` | Remove inline style or use the \`textColor\` prop |
| Form label click doesn't focus input | Missing \`htmlFor\` prop | \`<Typography variant="label" htmlFor="inputId">\` |

<Callout type="warning" title="Next.js / SSR">
  Typography relies heavily on CSS custom properties for responsive scaling. If you see FOUC (Flash of Unstyled Content) regarding font sizes, ensure your base theme CSS is loaded in the \`_app.tsx\` or root layout file.
</Callout>

### Frequently Asked Questions

**Q: Should I use Typography for buttons?**
A: No, use the Button component. However, the Button component uses the \`button\` typography variant internally for text styling.

**Q: Can I add custom fonts?**
A: Yes, you can override the \`--lxs-font-family-sans\` CSS variable globally to change the font family across all Typography instances.

**Q: How does the gradient prop work?**
A: It applies a \`linear-gradient(135deg, ...)\` as a background image, and uses \`-webkit-background-clip: text\` with transparent text fill color to create the gradient effect.

**Q: Why does my text not break when I use \`breakWord\`?**
A: Ensure the container has a defined width or \`max-width\`. If the container grows infinitely, the text will never need to break.
