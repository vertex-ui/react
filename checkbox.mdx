## Checkbox Best Practices

Checkboxes are standard UI elements. Stick to conventions so users aren't surprised.

<DoAndDont
  good={`// ✅ Use the label prop for proper accessible wrapping
<Checkbox label="Save payment method" />`}
  bad={`// ❌ Try to wrap it manually or use children
<div>
  <Checkbox />
  <span>Save payment method</span>
</div>`}

<DoAndDont
  good={`// ✅ Use indeterminate for "Select All" logic

## Checkbox Accessibility Guide

Checkbox follows the Native Checkbox pattern and meets WCAG AA. It uses a real, visually hidden `<input type="checkbox">` to guarantee perfect native accessibility.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the checkbox |
| <KeyboardKey>Space</KeyboardKey> | Toggles the checked state |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `aria-invalid` | `"true"` | When `error` is true |
| `aria-describedby` | `"[id]"` | Automatically links the native input to the `helperText` if provided |

### Screen Reader Behavior

When a user focuses the Checkbox, the screen reader announces the `label` text, the role ("checkbox"), and its current state ("checked" or "unchecked"). If `error` is true, it will announce "invalid data". It will also read the `helperText` immediately after the label.

### Accessibility Checklist

- [ ] Always use the `label` prop. Do not use floating text next to a Checkbox.
- [ ] If relying on colors to convey state (like red for error), also use the `error` prop or `helperText`.
- [ ] Do not use `disabled` for items that users need to discover; disabled inputs are skipped by screen readers.
- [ ] Always test with keyboard-only navigation before shipping

## Checkbox Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Checkbox without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-checkbox-size` | `20px` (md) | Width and height of the box |
| `--lxs-checkbox-border-width` | `2px` | Thickness of the box outline |
| `--lxs-checkbox-color` | `var(--lxs-color-primary-600)` | Fill color when checked |
| `--lxs-checkbox-hover-color` | `var(--lxs-color-primary-700)` | Fill color on hover when checked |

**Override globally:**
```css
:root {
  --lxs-checkbox-color: var(--lxs-color-brand-purple);
}
```

**Override for one section:**
```css
.danger-zone {
  --lxs-checkbox-color: var(--lxs-color-error-600);
}
```

**Override on one instance:**
```tsx
<Checkbox
  style={{ '--lxs-checkbox-color': '#000000' } as React.CSSProperties}
  label="Custom black checkbox"
/>
```

### Select All Table Header

Used when: Implementing bulk actions for a list of items.

<!--
EXAMPLE: Select All Table Header
PURPOSE: Demonstrates managing indeterminate state for a group
OUTPUT: A parent checkbox that controls child checkboxes
USE WHEN: Managing lists, tables, or bulk actions
SOURCE: Common usage pattern for Checkbox
-->
```tsx
import { useState } from 'react';
import { Checkbox } from '@luxis-ui/core';

export default function SelectAllPattern() {
  const allItems = ['Invoice #101', 'Invoice #102', 'Invoice #103'];
  const [selected, setSelected] = useState<string[]>(['Invoice #101']);

  const allChecked = selected.length === allItems.length;
  const isIndeterminate = selected.length > 0 && selected.length < allItems.length;

  const handleSelectAll = (checked: boolean) => {
    setSelected(checked ? allItems : []);
  };

  const handleSelectOne = (item: string, checked: boolean) => {
    setSelected(prev =>
      checked ? [...prev, item] : prev.filter(i => i !== item)
    );
  };

  return (
    <div style={{ display: 'flex', flexDirection: 'column', gap: '8px', padding: '16px', border: '1px solid #e5e5e5', borderRadius: '8px' }}>
      <Checkbox
        label={<strong style={{ fontSize: '14px' }}>Select All</strong>}
        checked={allChecked}
        indeterminate={isIndeterminate}
        onChange={(e) => handleSelectAll(e.target.checked)}
      />
      <hr style={{ width: '100%', margin: '4px 0', border: 'none', borderTop: '1px solid #e5e5e5' }} />
      <div style={{ display: 'flex', flexDirection: 'column', gap: '8px', paddingLeft: '24px' }}>
        {allItems.map(item => (
          <Checkbox
            key={item}
            label={item}
            checked={selected.includes(item)}
            onChange={(e) => handleSelectOne(item, e.target.checked)}
          />
        ))}
      </div>
    </div>
  );
}
```

## Troubleshooting Checkbox

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Clicking the text doesn't check the box | Passing text as children | Using the `label` prop |
| Indeterminate state doesn't submit | Expecting indeterminate to be a value | It's just visual; value is still checked/unchecked |
| Multiple checkboxes don't group | Building manual arrays | Use the `CheckboxGroup` component |
| Screen reader says "unlabeled checkbox" | Omitting the `label` prop | Always provide a `label` |

### Frequently Asked Questions

**Q: How do I change the color of the checkmark icon itself?**
A: The checkmark is an SVG stroke. You can override it via CSS targeting `.lxs-checkbox-icon { color: red; }` if you don't want the default white.

**Q: Can I use Checkbox without a label?**
A: If you truly need a standalone checkbox (e.g., in a table column), you must provide an `aria-label` attribute so screen readers know what it does.

**Q: Why does my onChange fire twice?**
A: In React Strict Mode during development, renders happen twice. Checkbox uses standard React events, so this is normal dev behavior and won't happen in production.

**Q: Does indeterminate mean the value is null or undefined?**
A: No, in HTML, indeterminate is purely a visual state. The underlying `checked` property is still either `true` or `false`.
