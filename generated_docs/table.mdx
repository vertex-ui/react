## Table Accessibility Guide

Table follows the table WAI-ARIA pattern and meets WCAG AA standards.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the Table |
| <KeyboardKey>Space</KeyboardKey> | Activates or selects within Table |
| <KeyboardKey>Enter</KeyboardKey> | Submits or executes default action for Table |
| <KeyboardKey>ArrowDown</KeyboardKey> | Navigates through internal options if applicable |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"table"` | Applied to establish the structural meaning of Table |
| `aria-label` | string | When no visible text label exists |
| `aria-disabled` | `"true" | undefined` | When the Table is explicitly disabled |

### Screen Reader Behavior

When focused, screen readers will announce the element as a table role, followed by any computed label. Interactions will update screen reader context dynamically depending on ARIA live regions if the Table manages dynamic state updates.

### Accessibility Checklist

- [ ] Ensure focus outlines are clearly visible against all backgrounds
- [ ] Confirm that all interactive areas are reachable via Tab key
- [ ] Provide descriptive `aria-label`s for icon-only or ambiguous instances
- [ ] Always test with keyboard-only navigation before shipping

## Table Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Table without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-table-bg` | `var(--lxs-color-neutral-0)` | Background color of Table |
| `--lxs-table-text` | `var(--lxs-color-neutral-900)` | Text color of Table |
| `--lxs-table-border` | `var(--lxs-color-neutral-300)` | Border color of Table |

**Override globally:**
```css
:root {
  --lxs-table-bg: var(--lxs-color-primary-50);
}
```

**Override for one section:**
```css
.my-section {
  --lxs-table-bg: var(--lxs-color-primary-50);
}
```

**Override on one instance:**
```tsx
<Table
  style={{ '--lxs-table-bg': 'var(--lxs-color-primary-50)' }}
/>
```

## Troubleshooting Table

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Not accepting focus | Omitting tabIndex on custom wrapper | Apply `tabIndex={0}` or rely on native focus |
| Events not firing | Attaching handlers to internal nodes | Attach standard events like `onClick` to the root wrapper |
| Styles not updating | Hardcoding conflicting inline styles | Prefer CSS variables or precise className selectors |
| Screen readers silent | Missing accessible name | Add an explicit `aria-label` or wrapping `<label>` element |

<Callout type="warning" title="Next.js / SSR">
  Ensure Table correctly serializes its initial state. If utilizing dynamic hooks, wrap it in a Client Component declaration.
</Callout>

### Frequently Asked Questions

**Q: Why does Table render poorly on mobile devices?**
A: Ensure your viewport meta tag is configured correctly. Table relies on standard CSS variables which should be responsive by default, but complex nested variants might require specific mobile-focused styling via design tokens.

**Q: Can I integrate Table with form validation libraries like Yup or Zod?**
A: Yes. Because Table utilizes native HTML patterns where possible, standard controlled component patterns using `onChange` and passing the `value` or `error` strings map seamlessly to form library controllers.

**Q: How do I change the default width of Table?**
A: You can set a specific width via `className`, or set `fullWidth={true}` (if supported) to have it fill its container. Inline styles via `style={{ width: '300px' }}` are also completely valid.

**Q: Does Table support dynamic loading?**
A: If Table provides a `loading` prop, setting it to true will toggle the appropriate WAI-ARIA loading states and display an internal spinner or placeholder according to the WAI-ARIA progressbar spec.
