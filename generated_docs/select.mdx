```tsx
  return (
    <Select value={value} onChange={(e) => setValue(e.target.value)} />
  );
}
```

## Select Accessibility Guide

Select follows the listbox WAI-ARIA pattern and meets WCAG AA standards.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the Select |
| <KeyboardKey>Space</KeyboardKey> | Activates or selects within Select |
| <KeyboardKey>Enter</KeyboardKey> | Submits or executes default action for Select |
| <KeyboardKey>ArrowDown</KeyboardKey> | Navigates through internal options if applicable |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"listbox"` | Applied to establish the structural meaning of Select |
| `aria-label` | string | When no visible text label exists |
| `aria-disabled` | `"true" | undefined` | When the Select is explicitly disabled |

### Screen Reader Behavior

When focused, screen readers will announce the element as a listbox role, followed by any computed label. Interactions will update screen reader context dynamically depending on ARIA live regions if the Select manages dynamic state updates.

### Accessibility Checklist

- [ ] Ensure focus outlines are clearly visible against all backgrounds
- [ ] Confirm that all interactive areas are reachable via Tab key
- [ ] Provide descriptive `aria-label`s for icon-only or ambiguous instances
- [ ] Always test with keyboard-only navigation before shipping

## Select Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Select without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-select-bg` | `var(--lxs-color-neutral-0)` | Background color of Select |
| `--lxs-select-text` | `var(--lxs-color-neutral-900)` | Text color of Select |
| `--lxs-select-border` | `var(--lxs-color-neutral-300)` | Border color of Select |

**Override globally:**
```css
:root {
  --lxs-select-bg: var(--lxs-color-primary-50);
}
```

**Override for one section:**
```css
.my-section {
  --lxs-select-bg: var(--lxs-color-primary-50);
}
```

**Override on one instance:**
```tsx
<Select
  style={{ '--lxs-select-bg': 'var(--lxs-color-primary-50)' }}
/>
```

### Frequently Asked Questions

**Q: Why does Select render poorly on mobile devices?**
A: Ensure your viewport meta tag is configured correctly. Select relies on standard CSS variables which should be responsive by default, but complex nested variants might require specific mobile-focused styling via design tokens.

**Q: Can I integrate Select with form validation libraries like Yup or Zod?**
A: Yes. Because Select utilizes native HTML patterns where possible, standard controlled component patterns using `onChange` and passing the `value` or `error` strings map seamlessly to form library controllers.

**Q: How do I change the default width of Select?**
A: You can set a specific width via `className`, or set `fullWidth={true}` (if supported) to have it fill its container. Inline styles via `style={{ width: '300px' }}` are also completely valid.

**Q: Does Select support dynamic loading?**
A: If Select provides a `loading` prop, setting it to true will toggle the appropriate WAI-ARIA loading states and display an internal spinner or placeholder according to the WAI-ARIA progressbar spec.
