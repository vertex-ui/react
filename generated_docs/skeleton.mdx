  Use the controlled pattern when syncing with a URL param, form
  library, or another component.
</Callout>

## Skeleton Best Practices

Proper implementation of Skeleton is essential for accessible and robust user interfaces.

  good={`// ✅ Use explicit labels or helper text

## Skeleton Accessibility Guide

Skeleton follows the progressbar WAI-ARIA pattern and meets WCAG AA standards.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the Skeleton |
| <KeyboardKey>Space</KeyboardKey> | Activates or selects within Skeleton |
| <KeyboardKey>Enter</KeyboardKey> | Submits or executes default action for Skeleton |
| <KeyboardKey>ArrowDown</KeyboardKey> | Navigates through internal options if applicable |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"progressbar"` | Applied to establish the structural meaning of Skeleton |
| `aria-label` | string | When no visible text label exists |
| `aria-disabled` | `"true" | undefined` | When the Skeleton is explicitly disabled |

### Screen Reader Behavior

When focused, screen readers will announce the element as a progressbar role, followed by any computed label. Interactions will update screen reader context dynamically depending on ARIA live regions if the Skeleton manages dynamic state updates.

### Accessibility Checklist

- [ ] Ensure focus outlines are clearly visible against all backgrounds
- [ ] Confirm that all interactive areas are reachable via Tab key
- [ ] Provide descriptive `aria-label`s for icon-only or ambiguous instances
- [ ] Always test with keyboard-only navigation before shipping

## Skeleton Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Skeleton without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-skeleton-bg` | `var(--lxs-color-neutral-0)` | Background color of Skeleton |
| `--lxs-skeleton-text` | `var(--lxs-color-neutral-900)` | Text color of Skeleton |
| `--lxs-skeleton-border` | `var(--lxs-color-neutral-300)` | Border color of Skeleton |

**Override globally:**
```css
:root {
  --lxs-skeleton-bg: var(--lxs-color-primary-50);
}
```

**Override for one section:**
```css
.my-section {
  --lxs-skeleton-bg: var(--lxs-color-primary-50);
}
```

**Override on one instance:**
```tsx
<Skeleton
  style={{ '--lxs-skeleton-bg': 'var(--lxs-color-primary-50)' }}
/>
```

## Troubleshooting Skeleton

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Not accepting focus | Omitting tabIndex on custom wrapper | Apply `tabIndex={0}` or rely on native focus |
| Events not firing | Attaching handlers to internal nodes | Attach standard events like `onClick` to the root wrapper |
| Styles not updating | Hardcoding conflicting inline styles | Prefer CSS variables or precise className selectors |
| Screen readers silent | Missing accessible name | Add an explicit `aria-label` or wrapping `<label>` element |

<Callout type="warning" title="Next.js / SSR">
  Ensure Skeleton correctly serializes its initial state. If utilizing dynamic hooks, wrap it in a Client Component declaration.
</Callout>

### Frequently Asked Questions

**Q: Why does Skeleton render poorly on mobile devices?**
A: Ensure your viewport meta tag is configured correctly. Skeleton relies on standard CSS variables which should be responsive by default, but complex nested variants might require specific mobile-focused styling via design tokens.

**Q: Can I integrate Skeleton with form validation libraries like Yup or Zod?**
A: Yes. Because Skeleton utilizes native HTML patterns where possible, standard controlled component patterns using `onChange` and passing the `value` or `error` strings map seamlessly to form library controllers.

**Q: How do I change the default width of Skeleton?**
A: You can set a specific width via `className`, or set `fullWidth={true}` (if supported) to have it fill its container. Inline styles via `style={{ width: '300px' }}` are also completely valid.

**Q: Does Skeleton support dynamic loading?**
A: If Skeleton provides a `loading` prop, setting it to true will toggle the appropriate WAI-ARIA loading states and display an internal spinner or placeholder according to the WAI-ARIA progressbar spec.
