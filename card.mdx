# Card

<ComponentStatus status="stable" version="1.0.0" aria="N/A" />

Cards are versatile containers used to group related information and actions together. They provide a clear visual boundary and hierarchy, making them ideal for dashboards, product listings, and summary views.

  It simplifies the API by using props for headers and footers instead of requiring multiple nested child components.

## Before You Start

A Card is a block-level container element that visually isolates chunks of content.
It renders as a standard `div` but provides built-in spacing, shadows, and borders.
The Quick Start example below will produce a simple, elevated white box containing text.

### Controlled Card

When to use: When a parent component needs to read or drive the state.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default Card manages its own state (uncontrolled).
  Use the controlled pattern when syncing with a URL param, form
  library, or another component.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: useState-driven Card with external state management
OUTPUT: Card whose state is owned by the parent
USE WHEN: Programmatically reading or setting component state
SOURCE: Derived from Card.tsx controlled/uncontrolled pattern
-->
```tsx
import { useState } from 'react';
import { Card } from '@luxis-ui/core';

export default function ControlledExample() {
  // Cards don't have intrinsic dynamic value state, but we can control their variant
  const [isActive, setIsActive] = useState(false);

  return (
    <div style={{ display: 'flex', flexDirection: 'column', gap: '16px' }}>
      <button onClick={() => setIsActive(!isActive)}>
        Toggle Active State
      </button>
      <Card variant={isActive ? 'elevated' : 'outlined'}>
        Status: {isActive ? 'Active (Elevated)' : 'Inactive (Outlined)'}
      </Card>
    </div>
  );
}
```

## Card Best Practices

Cards are layout workhorses, but they must be used carefully to avoid cluttered and confusing interfaces.

<DoAndDont
  good={`// ✅ Use specific content zones
<Card header={<h2>Title</h2>} footer={<button>Save</button>}>
  <p>Main content here.</p>
</Card>`}
  bad={`// ❌ Put everything in the body manually
<Card>
  <h2>Title</h2>
  <hr />
  <p>Main content here.</p>
  <hr />
  <button>Save</button>
</Card>`}
/>

<DoAndDont
  good={`// ✅ Make the whole card clickable for a single action
<Card clickable onClick={() => navigate('/details')}>
  <h3>View Details</h3>
</Card>`}
  bad={`// ❌ Nest multiple conflicting interactive elements
<Card clickable onClick={() => navigate('/details')}>
  <h3>View Details</h3>
  <button onClick={(e) => { e.stopPropagation(); deleteItem(); }}>Delete</button>
</Card>`}
/>

<DoAndDont
  good={`// ✅ Use full-bleed images with noPadding
<Card noPadding>
  <img src="banner.jpg" alt="Campaign banner" />
  <div style={{ padding: '16px' }}>Content below image</div>
</Card>`}
  bad={`// ❌ Try to override padding manually with negative margins
<Card>
  <img src="banner.jpg" alt="Campaign banner" style={{ margin: '-16px' }} />
</Card>`}
/>

<DoAndDont
  good={`// ✅ Choose a semantic variant
<Card variant="filled">
  Secondary info here
</Card>`}
  bad={`// ❌ Hardcode colors that break themes
<Card style={{ backgroundColor: '#fafafa' }}>
  Secondary info here
</Card>`}
/>

## Card Accessibility Guide

Card acts primarily as a visual container and doesn't inherently enforce a specific ARIA role unless made interactive.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the card (if `clickable` or natively focusable) or its interactive children |
| <KeyboardKey>Enter</KeyboardKey> | Activates `onClick` if the card has focus |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | implicitly `group` or none | Depends on how it is used; by default it's a structural `div` |

### Screen Reader Behavior

A screen reader will read the contents of the card sequentially from top to bottom.
If you use the `header` prop, it's good practice to provide a heading element (e.g., `<h3>`) inside it so users can navigate by headings. If the card is purely decorative, ensure any interactive children are properly labeled.

### Accessibility Checklist

- [ ] Ensure focusable elements inside the card have clear focus states.
- [ ] If `clickable` is true, avoid nesting other focusable elements inside the card.
- [ ] Provide semantic headings within the `header` prop for structure.
- [ ] Always test with keyboard-only navigation before shipping

## Card Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Card without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-card-bg` | `var(--lxs-color-white)` | Background color of the card body |
| `--lxs-card-padding` | `16px` (varies by size) | Internal padding for content, header, and footer |

**Override globally:**
```css
:root {
  --lxs-card-bg: var(--lxs-color-surface-elevated);
}
```

**Override for one section:**
```css
.dark-section {
  --lxs-card-bg: #1a1a1a;
}
```

**Override on one instance:**
```tsx
<Card
  style={{ '--lxs-card-bg': '#f0f8ff' } as React.CSSProperties}
>
  Content
</Card>
```

## Troubleshooting Card

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Margins look broken on headers | Manually adding `<hr>` | Using the `divider` prop |
| Full-bleed image has white borders | Forgetting `noPadding` | Using `<Card noPadding>` |
| Interactive children cause double-clicks | Setting `clickable` on a card with buttons | Avoid `clickable` if card has actions |
| Hard to distinguish background | Using 'filled' on a gray page | Use 'elevated' or 'outlined' |

### Frequently Asked Questions

**Q: How do I change the border radius of a single Card?**
A: Use the inline style object to override the internal variable: `style={{ borderRadius: '4px' }}`. The CSS class ensures the variable applies locally without fighting specificity.

**Q: Why doesn't the clickable prop make my card an `<a>` tag?**
A: The `clickable` prop applies CSS and visual states (like pointer cursor and active scaling) but does not change the HTML element from a `div`. Wrap the card content in a semantic link or use `onClick` for client-side routing.

**Q: Can I use multiple cards in a grid?**
A: Yes, cards are naturally fluid and stretch to fit their container. Wrap them in a CSS Grid or Flexbox layout parent to manage columns.

**Q: How do I remove the shadow entirely?**
A: Set the `variant` prop to `"outlined"` or `"filled"`.
