# Header

<ComponentStatus status="stable" version="1.0.0" aria="Application Region" />

The Header component provides a standardized top application bar, commonly used in dashboards. It encapsulates complex UI patterns like notification panels and user profile dropdowns into a simple, declarative API.

<Callout type="info" title="Migrating from another library?">
  Unlike general-purpose containers like MUI's `AppBar`, Luxis UI's `Header` is an opinionated, feature-rich component. It provides built-in state management for user and notification dropdowns.
</Callout>

## Before You Start

Header is designed to sit at the top of your application shell. It expects a `title` and optionally a `logo`. If you provide `notifications` or `userName`, it will automatically render the corresponding interactive elements. The Quick Start example below will produce a complete admin header.

<Callout type="tip" title="New to Luxis UI?">
  The Header automatically becomes sticky by default (`sticky={true}`), staying fixed at the top of the viewport as the user scrolls.
</Callout>

### Controlled Notifications

When to use: When a parent component needs to read or drive the state.

<Callout type="info" title="Controlled vs Uncontrolled">
  The Header internally manages the open/closed state of the dropdowns. However, the data for notifications must be passed in and updated by the parent component (e.g., marking items as read).
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: State-driven Header notifications
OUTPUT: A header where clicking notifications marks them as read
USE WHEN: Syncing read/unread state with a backend
SOURCE: Derived from Header.tsx and NotificationItem structure
-->
```tsx
import { useState } from 'react';
import { Header } from '@luxis-ui/core';

export default function ControlledExample() {
  const [notifs, setNotifs] = useState([
    { id: '1', title: 'Server alert', time: 'Just now', type: 'error' as const, read: false },
    { id: '2', title: 'New user joined', time: '10m ago', type: 'info' as const, read: false }
  ]);

  const handleMarkAllAsRead = () => {
    setNotifs(notifs.map(n => ({ ...n, read: true })));
  };

  const handleNotificationClick = (item: any) => {
    setNotifs(notifs.map(n => n.id === item.id ? { ...n, read: true } : n));
  };

  return (
    <Header
      title="Alert Center"
      notifications={notifs}
      onMarkAllAsRead={handleMarkAllAsRead}
      onNotificationClick={handleNotificationClick}
    />
  );
}
```

## Header Accessibility Guide

Header renders a semantic `<header>` tag.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Focuses interactive elements (toggle, actions, buttons) |
| <KeyboardKey>Enter</KeyboardKey> | Opens dropdowns or triggers actions |
| <KeyboardKey>Escape</KeyboardKey> | Closes open dropdown panels |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `aria-label` | `"Toggle sidebar"` | On the hamburger menu button |
| `aria-label` | `"Notifications"` | On the bell icon button |
| `aria-label` | `"User menu"` | On the user profile trigger |

### Screen Reader Behavior

Screen readers will announce the header region. The internal icon buttons have appropriate aria-labels so a user will hear "Toggle sidebar button", "Notifications button", etc. Unread notification counts are visually hidden but generally read out contextually if they receive focus or aria-live is implemented externally.

### Accessibility Checklist

- [ ] Provide a `title` or `logo` that helps identify the application.
- [ ] If using custom icons in `actions`, ensure they have `aria-label` properties.
- [ ] Always verify with keyboard-only navigation before shipping

## Header Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions like colors, spacing, and radius. Override them to restyle Header without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-header-bg` | `var(--lxs-background-primary)` | The background color of the header |
| `--lxs-header-height` | `64px` | Standard height of the header (adjusts on mobile automatically) |
| `--lxs-z-header` | `100` | The z-index applied when sticky |

**Override globally:**
```css
:root {
  --lxs-header-bg: #1e293b;
}
```

**Override for one instance:**
```tsx
<Header
  title="Dark Header"
  style={{ '--lxs-header-bg': '#000' } as React.CSSProperties}
/>
```

## Troubleshooting Header

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Toggle button doesn't show | Not providing `onToggleSidebar` | `<Header onToggleSidebar={() => {}} />` |
| Notifications don't update | Mutating state directly | Use `setNotifs` to pass a new array |
| Header overlaps content | Missing padding on main content area | Add `paddingTop: 64px` to your `<main>` element if not using a layout wrapper |
| Z-index issues with modals | Custom CSS breaking stacking | Leave default z-index or adjust tokens carefully |

### Frequently Asked Questions

**Q: How do I change the user menu dropdown position?**
A: The user menu position is managed internally by the Header to ensure it aligns correctly with the right edge. Customizing it requires overriding internal CSS, which is not recommended.

**Q: Can I use my own notification dropdown instead of the built-in one?**
A: Yes, you can omit the `notifications` prop and instead pass your custom component into the `actions` prop.

**Q: How do I get the user's initials to show if they don't have an avatar?**
A: If you pass `userName="John Doe"` but omit `userAvatar`, the component automatically extracts "JD" and displays it as a fallback.


**Q: How do I style the mobile sidebar toggle button?**
A: You can target it with the class `.lxs-header-toggle` in your custom CSS, or pass custom icons if supported by your application layout.
