## Before You Start

Toast represents a transient message alerting the user of an event.
It is based on the HTML `role="alert"` and `aria-live="polite"` patterns.
The Quick Start example below will produce a basic notification that dismisses itself after 5 seconds.

  Check out our Getting Started guide to learn about our design principles and theme configuration.

## How to Use Toast in React

The minimum code to render a working Toast:

<!--
EXAMPLE: Basic Usage
PURPOSE: Minimum viable implementation of Toast
OUTPUT: A simple default toast message
USE WHEN: Showing a standard notification
SOURCE: Derived from Toast.tsx defaults and simplest Story
-->
```tsx
import { Toast } from '@luxis-ui/core';

export default function Example() {
  return (
    // Note: In a real app, you would typically use useToast() to trigger this
    // The Toast component requires id, isVisible, createdAt, and onDismiss props
    <Toast
      id="toast-1"
      isVisible={true}
      createdAt={Date.now()}
      onDismiss={() => {}}
      variant="default"
    >
      This is a toast notification.
    </Toast>
  );
}
```

This renders a default-styled toast with a blue left border, an icon, and a progress bar that drains over 5 seconds.

### Controlled Toast

When to use: When a parent component needs to read or drive the state.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default Toast manages its own state (uncontrolled).
  Use the controlled pattern when syncing with a URL param, form
  library, or another component.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: useState-driven Toast with external state management
OUTPUT: Toast whose state is owned by the parent
USE WHEN: Programmatically reading or setting component state
SOURCE: Derived from Toast.tsx controlled/uncontrolled pattern
-->
```tsx
import { useState } from 'react';
import { Toast } from '@luxis-ui/core';

export default function ControlledExample() {
  const [isVisible, setIsVisible] = useState(true);

  if (!isVisible) return null;

  return (
    <Toast
      id="controlled-toast"
      isVisible={isVisible}
      createdAt={Date.now()}
      onDismiss={() => setIsVisible(false)}
      variant="default"
    >
      This is a controlled toast.
    </Toast>
  );
}
```

## Toast Best Practices

Following best practices ensures your notifications are helpful rather than annoying.

<DoAndDont
  good={`// ✅ Keep messages concise
<Toast variant="success">
  Profile updated.
</Toast>`}
  bad={`// ❌ Avoid long paragraphs in toasts
<Toast variant="success">
  Your profile has been successfully updated in our database. You can now navigate to the dashboard to see the changes applied.
</Toast>`}
/>

<DoAndDont
  good={`// ✅ Provide an action for undoing mistakes
<Toast
  variant="warning"
  action={{ label: 'Undo', onClick: handleUndo }}
  autoClose={8000}
>
  Conversation deleted
</Toast>`}
  bad={`// ❌ Don't auto-close toasts that require complex actions quickly
<Toast
  variant="warning"
  action={{ label: 'Undo', onClick: handleUndo }}
  autoClose={2000}
>
  Conversation deleted
</Toast>`}
/>

<DoAndDont
  good={`// ✅ Use the correct semantic variant
<Toast variant="error">
  Failed to connect to the server.
</Toast>`}
  bad={`// ❌ Don't use default/success for errors
<Toast variant="success">
  Failed to connect to the server.
</Toast>`}
/>

<DoAndDont
  good={`// ✅ Disable autoClose for critical errors
<Toast variant="error" autoClose={false}>
  Your session has expired. Please log in again.
</Toast>`}
  bad={`// ❌ Don't auto-close critical information
<Toast variant="error" autoClose={3000}>
  Your payment failed.
</Toast>`}
/>

## Toast Accessibility Guide

Toast follows the WAI-ARIA Alert pattern and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the action button or close button within the toast |
| <KeyboardKey>Enter</KeyboardKey> | Activates the focused button |
| <KeyboardKey>Space</KeyboardKey> | Activates the focused button |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| \`role\` | \`"alert"\` | Always on the container |
| \`aria-live\` | \`"polite"\` | Always on the container |
| \`aria-label\` | \`"Close notification"\` | On the close button |

### Screen Reader Behavior

When a toast is rendered, screen readers will immediately announce its contents because of the `role="alert"` and `aria-live="polite"` attributes. The polite setting ensures that the screen reader waits until the user finishes their current task or typing before speaking the notification, preventing interruption while still guaranteeing delivery.

### Accessibility Checklist

- [ ] Ensure critical messages use \`autoClose={false}\` so users have time to read them
- [ ] Provide clear, actionable text if an \`action\` button is included
- [ ] Test that screen readers announce the toast content when it appears
- [ ] Always test with keyboard-only navigation before shipping

## Troubleshooting Toast

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Toast vanishes too quickly for users to read | \`autoClose={1000}\` | \`autoClose={5000}\` or higher |
| Toast obscures important UI and won't close | \`closeButton={false}\` with \`autoClose={false}\` | Provide a close button or auto close |
| Screen readers announce toast multiple times | Multiple \`aria-live\` regions nested | Rely on the component's internal \`aria-live\` |
| Action button click event bubbles unexpectedly | \`onClick\` without \`e.stopPropagation()\` (if bubbling is an issue) | Handle events carefully within the action callback |

<Callout type="warning" title="Next.js / SSR">
  Toast relies on \`Date.now()\` and timers. Ensure you only render toasts on the client side, typically by triggering them via user interaction or within a \`useEffect\`.
</Callout>

### Frequently Asked Questions

**Q: How do I trigger a toast from anywhere in my app?**
A: You should use the \`useToast\` hook and \`ToastProvider\` instead of rendering the \`Toast\` component directly.

**Q: Can I change the position of the toasts?**
A: Yes, position is managed by the \`ToastContainer\`/Provider, usually set via a \`position\` prop (e.g., \`'top-right'\`).

**Q: Why doesn't my toast auto-close when I hover over it?**
A: By default, \`pauseOnHover\` is \`true\`. If you want it to close regardless of mouse position, set \`pauseOnHover={false}\`.

**Q: How do I remove the icon completely?**
A: Pass \`icon={false}\` to the Toast component.
