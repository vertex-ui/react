# Accordion

<ComponentStatus status="stable" version="1.0.0" aria="WAI-ARIA Accordion" />

The Accordion component renders a vertically stacked list of interactive headings that reveal or hide content. It solves the problem of presenting dense information in a limited space by allowing users to expand only the sections they care about. Use it for FAQ pages, complex settings, or step-by-step forms.

```bash
npm install @luxis-ui/core
# or
yarn add @luxis-ui/core
# or
pnpm add @luxis-ui/core
```
```tsx
import { Accordion } from '@luxis-ui/core';
```

<Callout type="info" title="Migrating from another library?">
  Luxis UI `Accordion` is equivalent to MUI's `<Accordion>`, Chakra UI's `<Accordion>`, and shadcn/ui's `Accordion`. The props are similar but Luxis UI provides a convenient `items` array prop for faster rendering without manually mapping sub-components.
</Callout>

## Before You Start

An accordion is a vertically stacked list of panels that each reveal or hide content when their header is clicked.

It is based on the standard WAI-ARIA Accordion pattern, ensuring full keyboard and screen reader accessibility.

The Quick Start example below will produce a clean, default-styled accordion with three interactive panels.

<Callout type="tip" title="New to Luxis UI?">
  Check out the Getting Started guide to learn how to set up the ThemeProvider, which ensures the accordion inherits your project's styling.
</Callout>

### Controlled Accordion

When to use: When you need to read or drive the component state from a parent.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default Accordion manages its own state (uncontrolled).
  Use the controlled pattern when a parent component needs to read or set
  the state — for example syncing with a URL param or a form library.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: useState-driven Accordion controlled by parent
OUTPUT: Accordion whose state is managed externally
USE WHEN: You need to programmatically read or set the component state
-->
```tsx
import { useState } from 'react';
import { Accordion } from '@luxis-ui/core';

const items = [
  { id: 'step1', header: 'Profile Details', children: <p>Form here...</p> },
  { id: 'step2', header: 'Payment Info', children: <p>Card details...</p> },
];

export default function ControlledExample() {
  // Start with no items open, or provide initial string[]
  const [openItems, setOpenItems] = useState<string[]>([]);

  return (
    <div>
      <div style={{ marginBottom: '16px' }}>
        <button onClick={() => setOpenItems(['step1'])}>Open Step 1</button>
        <button onClick={() => setOpenItems(['step2'])}>Open Step 2</button>
      </div>

      <Accordion
        items={items}
        openItems={openItems}
        onToggle={setOpenItems}
      />
    </div>
  );
}
```

## Accordion Best Practices

Using accordions effectively ensures users can find what they need without confusion or frustration.

<DoAndDont
  good={`// ✅ Use clear, descriptive headers
<Accordion items={[{
  id: 'billing',
  header: 'Update Billing Information'
}]} />`}
  bad={`// ❌ Use vague or excessively long headers
<Accordion items={[{
  id: 'billing',
  header: 'Click here to read more about how to update your credit card and other things'
}]} />`}
/>

<DoAndDont
  good={`// ✅ Enable allowMultiple if comparing sections is useful
<Accordion
  items={comparisonItems}
  allowMultiple={true}
/>`}
  bad={`// ❌ Force single open panel when users need context
<Accordion
  items={comparisonItems}
  allowMultiple={false}
/>`}
/>

<DoAndDont
  good={`// ✅ Use the flush variant in sidebars or cards
<Card>
  <Accordion variant="flush" items={sidebarItems} />
</Card>`}
  bad={`// ❌ Use bordered or separated variants inside containers
<Card>
  <Accordion variant="separated" items={sidebarItems} />
</Card>`}
/>

<DoAndDont
  good={`// ✅ Let the accordion manage its own state when possible
<Accordion items={items} />`}
  bad={`// ❌ Overcomplicate with unnecessary state management
const [open, setOpen] = useState([]);
<Accordion openItems={open} onToggle={setOpen} items={items} />`}
/>

## Accordion Accessibility Guide

Accordion follows the WAI-ARIA Accordion pattern
(https://www.w3.org/WAI/ARIA/apg/patterns/accordion/) and meets WCAG AA compliance.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the next accordion header. |
| <KeyboardKey>Shift</KeyboardKey> + <KeyboardKey>Tab</KeyboardKey> | Moves focus to the previous accordion header. |
| <KeyboardKey>Enter</KeyboardKey> | Toggles the expansion state of the focused item. |
| <KeyboardKey>Space</KeyboardKey> | Toggles the expansion state of the focused item. |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"region"` | Always on the content panel |
| `role` | `"button"` | Always on the header |
| `aria-expanded` | `true` \| `false` | Reflects current open state on the header and item wrapper |
| `aria-controls` | `"[id]"` | Links header to its content panel ID |
| `aria-labelledby`| `"[id]"` | Links content panel to its header ID |
| `aria-disabled` | `true` \| `false` | When an item is disabled |
| `aria-busy` | `true` \| `false` | When an item is loading |

### Screen Reader Behavior

When a user focuses an accordion header, the screen reader announces the header text, its role as a button, and its state (collapsed or expanded). Pressing Enter or Space toggles the state, and the screen reader will announce the state change immediately.

### Accessibility Checklist

- [ ] Ensure header text is descriptive and concise.
- [ ] Verify that custom icons (if used) have `aria-hidden="true"`.
- [ ] If animations are a concern for users with vestibular disorders, set `disableAnimations={true}`.
- [ ] Always test with keyboard-only navigation before shipping.

### FAQ Section with Expand All Button

Used when: Users might want to search text across all answers simultaneously.

<!--
EXAMPLE: FAQ Section with Expand All Button
PURPOSE: Demonstrates a controlled accordion with global toggle
OUTPUT: Accordion with a button that opens or closes all panels
USE WHEN: You have many text-heavy sections that users might Cmd+F search
SOURCE: Pattern derived from common usage of Accordion
-->
```tsx
import { useState } from 'react';
import { Accordion } from '@luxis-ui/core';

const faqItems = [
  { id: 'terms', header: 'Is my data secure?', children: <p>Yes, we use AES-256 encryption.</p> },
  { id: 'privacy', header: 'How to export data?', children: <p>Go to settings > Export.</p> },
];

export default function FaqSection() {
  const [openItems, setOpenItems] = useState<string[]>([]);
  const allIds = faqItems.map(item => item.id);
  const isAllOpen = openItems.length === faqItems.length;

  const toggleAll = () => {
    setOpenItems(isAllOpen ? [] : allIds);
  };

  return (
    <div>
      <div style={{ display: 'flex', justifyContent: 'flex-end', marginBottom: '16px' }}>
        <button onClick={toggleAll}>
          {isAllOpen ? 'Collapse All' : 'Expand All'}
        </button>
      </div>
      <Accordion
        items={faqItems}
        openItems={openItems}
        onToggle={setOpenItems}
        allowMultiple={true}
      />
    </div>
  );
}
```

### Multi-step Form Tracker

Used when: Building a wizard where users progress linearly but can review previous steps.

<!--
EXAMPLE: Multi-step Form Tracker
PURPOSE: Demonstrates a step-by-step accordion
OUTPUT: A controlled accordion that forces linear progression
USE WHEN: Users need to complete information in a specific sequence
SOURCE: Pattern derived from common usage of Accordion
-->
```tsx
import { useState } from 'react';
import { Accordion } from '@luxis-ui/core';

const formSteps = [
  { id: 'contact', header: '1. Contact Info', children: <p>Email and Phone</p> },
  { id: 'address', header: '2. Shipping Address', children: <p>Street and City</p> },
];

export default function MultiStepTracker() {
  const [currentStep, setCurrentStep] = useState(['contact']);

  return (
    <Accordion
      items={formSteps}
      openItems={currentStep}
      onToggle={(newItems) => {
        // Prevent closing the only open item
        if (newItems.length > 0) {
          setCurrentStep([newItems[newItems.length - 1]]);
        }
      }}
      collapsible={false}
    />
  );
}
```

## Troubleshooting Accordion

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Items won't stay open | Providing `openItems` without `onToggle` | Use both `openItems={state}` and `onToggle={setState}` |
| Cannot open multiple items | Setting `allowMultiple={false}` | Set `allowMultiple={true}` |
| Animations are jumpy | Using complex React nodes causing re-renders | Stabilize children components, or use `disableAnimations={true}` |
| "Void element" errors | Passing raw text directly inside Accordion | Use the `items` prop or wrap text in `<AccordionItem>` |

<Callout type="warning" title="Animation Performance">
  The Accordion uses CSS `max-height` transitions. If the content inside the accordion changes height dynamically *after* it opens (e.g. an image loading slowly), the animation might clip. Define explicit heights for inner media where possible.
</Callout>

### Frequently Asked Questions

**Q: How do I change the accordion icon?**
A: You can pass `iconType="plus-minus"` for an alternative preset, or pass specific React nodes to `expandedIcon` and `collapsedIcon` along with `iconType="custom"`.

**Q: Why doesn't clicking the header do anything?**
A: Make sure the `disabled` or `loading` props are not set to `true`, and that if you are using `openItems` (controlled mode), you are actively updating the state in the `onToggle` callback.

**Q: Can I put a form inside the accordion?**
A: Yes. However, be aware that pressing Enter while focused on a form input *might* trigger form submission depending on your setup. The accordion headers themselves listen to Enter to toggle, but this doesn't interfere with inputs inside the body.

**Q: How do I open a specific accordion item by default?**
A: For uncontrolled usage, pass an array of item IDs to the `defaultOpenItems` prop: `<Accordion defaultOpenItems={['luxis-intro']} items={items} />`.
