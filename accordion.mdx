## Before You Start

An accordion consists of a list of items where each item has a header and an expandable content area.
It implements the standard WAI-ARIA disclosure pattern with full keyboard and screen reader support.
The Quick Start below renders a standard accordion using the data-driven `items` prop.

  Check out the Getting Started guide to ensure your theme provider and base CSS are properly configured.

### Controlled Accordion

When to use: When a parent component needs to read or drive the state.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default Accordion manages its own state (uncontrolled).
  Use the controlled pattern when syncing with a URL param, form
  library, or another component.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: useState-driven Accordion with external state management
OUTPUT: Accordion whose state is owned by the parent
USE WHEN: Programmatically reading or setting component state
SOURCE: Derived from Accordion.tsx controlled/uncontrolled pattern
-->
```tsx
import { useState } from 'react';
import { Accordion } from '@luxis-ui/core';

export default function ControlledExample() {
  const [openItems, setOpenItems] = useState<string[]>([]);

  return (
    <div>
      <div style={{ marginBottom: '16px' }}>
        <button onClick={() => setOpenItems(['controlled1'])}>Open First</button>
        <button onClick={() => setOpenItems([])}>Close All</button>
      </div>
      <Accordion
        openItems={openItems}
        onToggle={(newOpenItems) => setOpenItems(newOpenItems)}
        items={[
          {
            id: 'controlled1',
            header: 'Controlled Panel 1',
            children: <p>This panel is managed by React state.</p>,
          },
          {
            id: 'controlled2',
            header: 'Controlled Panel 2',
            children: <p>State changes trigger the onToggle callback.</p>,
          },
        ]}
      />
    </div>
  );
}
```

## Accordion Best Practices

Using accordions correctly ensures content remains accessible and logical.

<DoAndDont
  good={`// ✅ Use clear, descriptive headers
<Accordion
  items={[
    { id: '1', header: 'How do I reset my password?', children: <p>...</p> }
  ]}
/>`}
  bad={`// ❌ Avoid vague headers requiring users to click to understand
<Accordion
  items={[
    { id: '1', header: 'More info', children: <p>...</p> }
  ]}
/>`}
/>

<DoAndDont
  good={`// ✅ Set allowMultiple=true when comparing information
<Accordion
  allowMultiple={true}
  items={[
    { id: 'plan-a', header: 'Basic Plan Details', children: <p>...</p> },
    { id: 'plan-b', header: 'Pro Plan Details', children: <p>...</p> }
  ]}
/>`}
  bad={`// ❌ Force users to memorize details from a closed panel
<Accordion
  allowMultiple={false}
  items={[
    { id: 'plan-a', header: 'Basic Plan Details', children: <p>...</p> },
    { id: 'plan-b', header: 'Pro Plan Details', children: <p>...</p> }
  ]}
/>`}
/>

<DoAndDont
  good={`// ✅ Use the items prop for data-driven rendering
<Accordion items={data.map(item => ({ id: item.id, header: item.title, children: item.content }))} />`}
  bad={`// ❌ Manually map over wrapper components when items prop is available
<Accordion>
  {data.map(item => (
    <AccordionItem key={item.id} id={item.id} header={item.title}>
      {item.content}
    </AccordionItem>
  ))}
</Accordion>`}
/>

<DoAndDont
  good={`// ✅ Provide a defaultOpenItem if content is important
<Accordion defaultOpenItems={['welcome']} items={[{ id: 'welcome', header: 'Welcome', children: <p>Start here</p> }]} />`}
  bad={`// ❌ Hide critical onboarding steps inside closed accordions
<Accordion items={[{ id: 'welcome', header: 'Welcome', children: <p>Start here</p> }]} />`}
/>

## Accordion Props & API Reference

Complete reference for all props. All types and defaults sourced directly

### Accordion Props

| Prop | Type | Default | Required | Description |
|------|------|---------|----------|-------------|
| `allowMultiple` | `boolean` | `false` | No | Whether multiple items can be open at once |
| `chevronPosition` | `'left' \| 'right'` | `'right'` | No | Position of the chevron icon |
| `children` | `ReactNode` | `undefined` | No | Children accordion items (alternative to items prop) |
| `className` | `string` | `""` | No | Custom class name |

## Accordion Accessibility Guide

Accordion follows the WAI-ARIA Accordion pattern and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the next accordion header. |
| <KeyboardKey>Enter</KeyboardKey> | Toggles the expanded/collapsed state of the focused header. |
| <KeyboardKey>Space</KeyboardKey> | Toggles the expanded/collapsed state of the focused header. |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"button"` | Always applied to the accordion header. |
| `role` | `"region"` | Always applied to the content panel. |
| `aria-expanded` | `"true" \| "false"` | Applied to header and reflects current state. |
| `aria-controls` | `string` | Links the header to its respective content panel ID. |
| `aria-labelledby` | `string` | Links the content panel to its respective header ID. |
| `aria-disabled` | `"true" \| "false"` | Set to true when the item or entire accordion is disabled. |

### Screen Reader Behavior

When navigating to an accordion header, the screen reader announces the header text, its role as a button, and its current state (expanded or collapsed). Pressing Enter toggles the state, and the screen reader announces the new state. When expanded, navigating forward moves focus into the content region, which is properly labelled by the header.

### Accessibility Checklist

- [ ] Ensure headers are descriptive and indicate what content will be revealed.
- [ ] Do not put critical actions solely inside collapsed accordion panels.
- [ ] Do not nest focusable interactive elements directly within the clickable area of the header.
- [ ] Always test with keyboard-only navigation before shipping.

## Troubleshooting Accordion

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Passing elements directly as children breaks data props | `<Accordion><div>...</div></Accordion>` | `<Accordion items={[{...}]} />` |
| Multiple panels won't open | `allowMultiple={false}` | `allowMultiple={true}` |
| Animations feel sluggish | Leaving default animations on heavy content | `disableAnimations={true}` |
| Interactive element in header causes hydration errors | `header={<button>Click</button>}` | `header={<span>Click</span>}` |

### Frequently Asked Questions

**Q: Can I use nested components inside the header?**
A: Yes, the `header` prop accepts React nodes. However, avoid nesting buttons or links inside the header, as the header itself is an interactive button.

**Q: How do I disable animation completely?**
A: Set the `disableAnimations` prop to `true` on the `Accordion` component.

**Q: Can I control which panels are open from a parent component?**
A: Yes, provide an array of IDs to the `openItems` prop and pass a function to `onToggle` to manage the state externally.

**Q: Does it support server-side rendering (SSR)?**
A: Yes, Accordion works flawlessly with SSR frameworks like Next.js and Remix.
