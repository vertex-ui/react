The Quick Start example below will produce a dark tooltip hovering above a button.

## Tooltip Best Practices

Always ensure tooltips contain supplementary text, not essential functionality.

<DoAndDont
  good={`// ✅ Use brief, descriptive text
<Tooltip content="Mark as unread">
  <IconButton icon={<MailIcon />} />
</Tooltip>`}
  bad={`// ❌ Don't include interactive forms inside tooltips
<Tooltip content={<SignupForm />}>
  <Button>Join Now</Button>
</Tooltip>`}
/>

<DoAndDont
  good={`// ✅ Wait before showing to prevent flashing
<Tooltip content="Settings" delay={300}>
  <IconButton icon={<SettingsIcon />} />
</Tooltip>`}
  bad={`// ❌ Don't set zero delay for everything
<Tooltip content="Settings" delay={0}>
  <IconButton icon={<SettingsIcon />} />
</Tooltip>`}
/>

<DoAndDont
  good={`// ✅ Set maximum widths for long text
<Tooltip content="A very long explanation that requires wrapping to be legible." maxWidth="250px">
  <InfoIcon />
</Tooltip>`}
  bad={`// ❌ Don't allow text to stretch endlessly
<Tooltip content="A very long explanation that requires wrapping to be legible.">
  <InfoIcon />
</Tooltip>`}
/>

<DoAndDont
  good={`// ✅ Make sure the trigger accepts focus
<Tooltip content="Submit form">
  <button>Submit</button>
</Tooltip>`}
  bad={`// ❌ Don't wrap non-focusable elements without adding tabindex
<Tooltip content="This is a div">
  <div>Static text</div>
</Tooltip>`}
/>

## Tooltip Accessibility Guide

Tooltip follows the WAI-ARIA Tooltip pattern and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Focuses the trigger element, which opens the tooltip |
| <KeyboardKey>Escape</KeyboardKey> | Closes the open tooltip and returns focus to the trigger |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"tooltip"` | Always on the portal container |
| `aria-describedby` | `"[id]"` | Added to the trigger element when the tooltip is visible |
| `aria-hidden` | `"true"` | On the visual arrow element |

### Screen Reader Behavior

When the user tabs to the trigger element, the tooltip opens automatically. Because the trigger receives the `aria-describedby` attribute linking it to the tooltip's ID, the screen reader will pause briefly after reading the trigger's label, then read the tooltip content. This provides contextual help without stealing focus.

### Accessibility Checklist

- [ ] Provide tooltips ONLY for non-essential information
- [ ] Ensure the \`children\` element can receive focus natively (e.g., \`<button>\` or \`<a>\`)
- [ ] Check color contrast if using the \`light\` variant
- [ ] Always test with keyboard-only navigation before shipping

## Tooltip Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Tooltip without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-tooltip-bg` | `var(--lxs-color-neutral-900)` | Background color of the dark tooltip |
| `--lxs-tooltip-color` | `var(--lxs-color-neutral-50)` | Text color of the dark tooltip |
| `--lxs-tooltip-border` | `transparent` | Border color |

**Override globally:**
```css
:root {
  --lxs-tooltip-bg: #1e293b;
}
```

**Override for one section:**
```css
.custom-theme {
  --lxs-tooltip-bg: #334155;
  --lxs-tooltip-color: #f8fafc;
}
```

**Override on one instance:**
```tsx
<Tooltip
  style={{ '--lxs-tooltip-bg': '#7e22ce' } as React.CSSProperties}
  content="Purple tooltip"
>
  <button>Hover</button>
</Tooltip>
```

## Troubleshooting Tooltip

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Tooltip doesn't appear | Wrapping a custom component that doesn't forward `onMouseEnter`/`onFocus` | Wrap a native DOM element or ensure your component forwards events |
| Tooltip gets cut off | Parent has `overflow: hidden` | Ensure the portal renders to `document.body` (default behavior) |
| Position is wrong when scrolling | Parent container transforms context | Tooltips use fixed positioning; ensure `document.body` is relative |
| Cannot tab to trigger | Wrapping a `<div>` or `<span>` without a `tabIndex` | Use `<button>` or add `tabIndex={0}` to static wrappers |

<Callout type="warning" title="Next.js / SSR">
  Tooltip uses \`createPortal\`. Ensure the component only renders its tooltip contents after the component has mounted on the client to avoid hydration mismatches.
</Callout>

### Frequently Asked Questions

**Q: Can I put a button inside the tooltip?**
A: No, tooltips should not contain interactive elements. If you need buttons or links, use a Popover component instead.

**Q: Why isn't my Tooltip closing when I move my mouse away quickly?**
A: Check the \`hideDelay\` prop. If it's set to a high number, the tooltip will persist briefly after the mouse leaves.

**Q: Can I trigger the tooltip on click instead of hover?**
A: Tooltip is designed for hover/focus interactions. For click-triggered popups, use a Popover or Dropdown menu.

**Q: How do I change the tooltip width?**
A: Pass the \`maxWidth\` prop (e.g., \`maxWidth="400px"\`). The tooltip will expand to fit its content up to that limit before wrapping text.
