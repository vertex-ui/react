# Avatar

<ComponentStatus status="stable" version="1.0.0" aria="WAI-ARIA img" />

The Avatar component is a visual representation of a user, organization, or specific entity. It elegantly handles edge cases like missing images or broken URLs by automatically falling back to generated text initials or a default icon. It supports multiple shapes, sizes, and absolutely positioned status indicators for building rich interfaces like chat apps or activity feeds.

## Before You Start

An avatar is a visual identifier, most commonly displayed as a circle containing a portrait.

It is based on the standard HTML `<img>` tag, but abstracts away the complexity of checking if an image URL is valid before trying to render it.

The Quick Start example below will render a standard user image, or gracefully fall back to displaying the letters "JD" if the image request fails.

<Callout type="tip" title="New to Luxis UI?">
  Check out the Getting Started guide to learn how to set up the ThemeProvider, which ensures the avatar fallback states inherit your project's typography and color tokens.
</Callout>

### Avatar Fallback States

When `src` is missing or fails to load, Avatar goes through a fallback sequence. It prioritizes the `fallback` string prop, then attempts to extract two initials from the `alt` string, and finally defaults to a generic `UserIcon`.

<!--
EXAMPLE: Fallback States
PURPOSE: Demonstrates automatic and explicit fallbacks
OUTPUT: Three avatars showing automatic initials, explicit initials, and a generic icon
USE WHEN: Images are optional or user-uploaded and prone to 404s
SOURCE: Pattern derived from Avatar.tsx internal logic
-->
```tsx
import { Avatar } from '@luxis-ui/core';

export default function FallbackExample() {
  return (
    <div style={{ display: 'flex', gap: '16px' }}>
      {/* 1. Extracts "AW" from the alt string automatically */}
      <Avatar alt="Alice Wonderland" />

      {/* 2. Uses the explicit fallback string */}
      <Avatar alt="System Bot" fallback="BOT" />

      {/* 3. Renders the default UserIcon when alt is empty */}
      <Avatar />
    </div>
  );
}
```

This ensures your UI never displays a broken image icon.

## Avatar Best Practices

Using avatars consistently helps users quickly parse complex data.

<DoAndDont
  good={`// ✅ Provide an alt attribute for accessibility and auto-initials
<Avatar src={user.image} alt={user.fullName} />`}
  bad={`// ❌ Omit alt, causing screen readers to ignore it and forcing a generic icon fallback
<Avatar src={user.image} />`}
/>

<DoAndDont
  good={`// ✅ Use priority for the main profile picture above the fold
<Avatar src={heroImage} alt="Profile" size="lg" priority={true} />`}
  bad={`// ❌ Use priority on lists of hundreds of users, destroying performance
{users.map(u => <Avatar src={u.image} alt="User" priority={true} />)}`}
/>

<DoAndDont
  good={`// ✅ Use shape to differentiate data types
<Avatar src={user.img} shape="circular" />
<Avatar src={company.logo} shape="rounded" />`}
  bad={`// ❌ Mix shapes randomly within the same list of data
<Avatar src={user1.img} shape="circular" />
<Avatar src={user2.img} shape="square" />`}
/>

<DoAndDont
  good={`// ✅ Use short fallback strings
<Avatar fallback="AD" alt="Admin Dashboard" />`}
  bad={`// ❌ Pass long strings into the fallback causing text overflow
<Avatar fallback="ADMIN" alt="Admin Dashboard" />`}
/>

## Avatar Accessibility Guide

The Avatar component follows standard image accessibility patterns, ensuring screen readers don't double-announce text when fallbacks are used.

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"img"` | Always on the wrapper div |
| `aria-label` | `[computed string]` | Always on wrapper. Evaluates `alt`, then `fallback`, then `"Avatar"`. |
| `aria-hidden` | `"true"` | Always on the inner fallback `span` |

### Screen Reader Behavior

By placing `role="img"` and `aria-label` on the outer `div`, the Avatar component ensures that screen readers announce the element as a single image node, regardless of whether it successfully loaded the `<img>` tag or is currently displaying CSS-styled fallback `<span>` text.

The inner text inside the fallback span is explicitly hidden from screen readers (`aria-hidden="true"`) to prevent the screen reader from incorrectly announcing "Image: Jane Doe, J D".

### Accessibility Checklist

- [ ] Always provide a descriptive `alt` tag (e.g. the user's full name).
- [ ] If the Avatar is purely decorative and accompanied by the user's name in text immediately next to it, consider passing `alt=""` and letting the adjacent text act as the label, to prevent screen readers from reading the name twice.
- [ ] Ensure the `statusIndicator` has its own visually hidden text or `aria-label` if it conveys state (e.g. "Online").

## Troubleshooting Avatar

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| "JD" initials read out loud by VoiceOver alongside the image | Using `span` wrappers manually | Trust the internal `Avatar` logic; it handles `aria-hidden` correctly |
| Image looks stretched or squished | Passing an image with a non-1:1 aspect ratio | The `img` tag uses `object-fit: cover` internally, ensuring it crops instead of stretching |
| Initials show "A " instead of "AB" | Passing `alt="A B"` | Ensure the alt text doesn't contain multiple leading spaces |
| LCP (Largest Contentful Paint) is slow | Leaving `priority` undefined | Set `priority={true}` on the single most important avatar on the page |

### Frequently Asked Questions

**Q: How do I change the color of the fallback initials?**
A: You can override the CSS variables `--lxs-avatar-bg` and `--lxs-avatar-color` on the component's `style` prop, or in your CSS stylesheet.

**Q: Can I use Next.js `<Image>` instead of the native `<img>`?**
A: Currently, the internal implementation uses a native `<img>` tag to allow for strict `onError` handling that triggers the fallback UI. If you need advanced Next.js image optimization, use the Luxis UI `Image` component.

**Q: How does the component decide what initials to use?**
A: If `fallback` is provided, it uses the first two characters of that string. If not, it splits the `alt` string by spaces. If there are two or more words, it takes the first letter of the first two words (e.g., "John Doe" -> "JD"). If there is only one word, it takes the first two letters of that word (e.g., "Apple" -> "AP").

**Q: Why is there a wrapper div instead of just an img tag?**
A: The wrapper `div` is necessary to establish a consistent layout boundary and background color so that if the network request for the image fails, the UI doesn't jump or collapse while the fallback span renders.
