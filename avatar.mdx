## Before You Start

An Avatar is fundamentally a styled image container. It uses `object-fit: cover` to ensure images fill the space regardless of their original aspect ratio.
The component handles its own error state, switching to a text or icon fallback if the `src` URL fails to load.

<Callout type="tip" title="New to Luxis UI?">
  The Avatar component inherits sizes from your Theme Provider, defaulting to `md` if not specified.
</Callout>

## Avatar Best Practices

Ensure avatars remain accessible and semantically correct.

<DoAndDont
  good={`// ✅ Always provide descriptive alt text
<Avatar src="user.jpg" alt="Sarah Chen profile picture" />`}
  bad={`// ❌ Leave alt text blank for meaningful images
<Avatar src="user.jpg" alt="" />`}
/>

<DoAndDont
  good={`// ✅ Use the priority prop if the avatar is the largest image on the page
<Avatar src="hero-user.jpg" priority={true} size="lg" />`}
  bad={`// ❌ Let large hero avatars load lazily, causing LCP issues
<Avatar src="hero-user.jpg" size="lg" />`}
/>

<DoAndDont
  good={`// ✅ Use shapes consistently to distinguish entity types
<Avatar src="org.png" shape="rounded" /> // Companies
<Avatar src="user.jpg" shape="circular" /> // People`}
  bad={`// ❌ Mix shapes randomly
<Avatar src="user.jpg" shape="square" />
<Avatar src="user2.jpg" shape="circular" />`}
/>

<DoAndDont
  good={`// ✅ Let the component calculate initials automatically
<Avatar src="user.jpg" alt="Jonathan Davis" />`}
  bad={`// ❌ Hardcode complex initials logic in the template
<Avatar src="user.jpg" fallback={userName.split(' ').map(n => n[0]).join('')} />`}

## Avatar Accessibility Guide

Avatar is structured to act as a single semantic image, regardless of whether it currently renders an actual `<img>` tag or fallback text.

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"img"` | Always applied to the outer wrapper `div`. |
| `aria-label` | `string` | Always applied to the wrapper, populated from `alt` or `fallback`. |
| `aria-hidden` | `"true"` | Applied to the internal fallback `span` to prevent double-announcements. |

### Screen Reader Behavior

Because the outer `div` has `role="img"` and an `aria-label`, screen readers treat the entire component as a standard image element. The internal `img` tag relies on standard behavior, while the internal `span` fallback is explicitly hidden from the tree. If the avatar is inside a link or button, the screen reader will announce it as part of the actionable element's name.

### Accessibility Checklist

- [ ] Ensure `alt` text describes the *purpose* or *identity* (e.g., "Sarah Chen"), not the image content (e.g., "Woman smiling").
- [ ] If the Avatar is purely decorative (e.g., next to a name that is already printed in text), add `aria-hidden="true"` to the Avatar component to avoid redundant screen reader announcements.
- [ ] Ensure any custom icons passed to `fallback` have `aria-hidden="true"` applied.

## Avatar Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions
  like colors, spacing, and radius. Override them to restyle
  Avatar without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-color-neutral-200` | `#e5e7eb` | Background color for fallbacks |
| `--lxs-color-neutral-700` | `#374151` | Text color for fallbacks |
| `--lxs-font-family-sans` | `system-ui, sans-serif` | Font family for initials |
| `--lxs-font-weight-medium` | `500` | Font weight for initials |
| `--lxs-radius-full` | `9999px` | Border radius for circular shape |
| `--lxs-radius-lg` | `8px` | Border radius for rounded shape |

**Override globally:**
```css
:root {
  --lxs-color-neutral-200: #e0f2fe; /* Light blue fallbacks */
}
```

**Override for one section:**
```css
.admin-list {
  --lxs-color-neutral-700: #0369a1; /* Dark blue text */
}
```

**Override on one instance:**
```tsx
<Avatar
  style={{ '--lxs-color-neutral-200': '#fce7f3' } as React.CSSProperties}
  fallback="JD"
/>
```

## Troubleshooting Avatar

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Image is distorted or stretched | Modifying `object-fit` manually | Let the component use its default `object-fit: cover`. |
| Browser shows broken image icon | Forcing a src that 404s without `onError` | The component handles errors automatically if you don't interfere with the `img` tag. |
| Fallback text is too long | `fallback="Alexander"` | `fallback="AL"` (keep it to 1-2 characters). |
| Screen reader says "image" twice | Leaving `alt="avatar"` on purely decorative avatars next to names | Add `aria-hidden="true"` to decorative avatars. |

### Frequently Asked Questions

**Q: Can I use `next/image` or another custom image component?**
A: Currently, Avatar renders a standard HTML `img` element internally. If you need optimized Next.js images, use the `next/image` component directly and apply your own border-radius styling.

**Q: Why is my `onImageError` callback firing immediately?**
A: Ensure the `src` URL is valid and accessible from the browser. CORS issues or blocked mixed-content requests will trigger an error instantly.

**Q: How does the priority prop work?**
A: Setting `priority={true}` applies `fetchPriority="high"` and `loading="eager"` to the underlying `img` tag, instructing the browser to prioritize the download over lazy-loaded elements.

**Q: Is the status indicator interactive?**
A: No, the `statusIndicator` is rendered inside the non-interactive `div` wrapper. If you need an interactive badge, position a button absolutely over the Avatar from the parent component.
