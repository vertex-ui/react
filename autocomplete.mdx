## Before You Start

Autocomplete is a controlled text input merged with an interactive dropdown listbox.
It manages keyboard navigation internally, ensuring screen readers understand the relationship between what the user types and what appears in the popup.
The Quick Start below expects an array of objects containing at least `label` and `value` keys.

<Callout type="tip" title="New to Luxis UI?">
  Ensure your project includes the base CSS file as described in the Getting Started guide for dropdown positioning to work correctly.
</Callout>

## How to Use Autocomplete in React

The minimum code to render a working Autocomplete:

<!--
EXAMPLE: Basic Usage
PURPOSE: Minimum viable implementation of Autocomplete
OUTPUT: A functional autocomplete input with three options
USE WHEN: Providing a basic search experience
SOURCE: Derived from Autocomplete.tsx defaults and simplest Story
-->
```tsx
import { Autocomplete } from '@luxis-ui/core';

export default function Example() {
  const frameworks = [
    { value: 'react', label: 'React' },
    { value: 'vue', label: 'Vue.js' },
    { value: 'angular', label: 'Angular' },
  ];

  return (
    <Autocomplete
      label="Framework"
      placeholder="Type to search..."
      options={frameworks}
      onSelect={(value, option) => console.log('Selected:', value)}
    />
  );
}
```

This renders a standard input that, when focused, opens a dropdown showing the options. Typing filters the list automatically.

### Controlled Autocomplete

When to use: When a parent component needs to read or drive the state.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default Autocomplete manages its own input value (uncontrolled).
  Use the controlled pattern when syncing with a form library or resetting values externally.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: useState-driven Autocomplete with external state management
OUTPUT: Autocomplete whose value is owned by the parent
USE WHEN: Programmatically reading or setting component state
SOURCE: Derived from Autocomplete.tsx controlled/uncontrolled pattern
-->
```tsx
import { useState } from 'react';
import { Autocomplete } from '@luxis-ui/core';

export default function ControlledExample() {
  const [value, setValue] = useState('');

  return (
    <div>
      <Autocomplete
        label="Controlled Input"
        value={value}
        onChange={(newValue) => setValue(newValue)}
        onSelect={(val) => setValue(val)}
        options={[{ value: 'opt1', label: 'Option 1' }]}
        clearable={true}
        onClear={() => setValue('')}
      />
      <div style={{ marginTop: '12px', fontSize: '14px', color: '#666' }}>
        Current state: <strong>{value || 'empty'}</strong>
      </div>
    </div>
  );
}
```

## Autocomplete Best Practices

Autocompletes are complex inputs. Following best practices prevents user frustration.

<DoAndDont
  good={`// ✅ Use minSearchLength for huge datasets to prevent lag
<Autocomplete options={hugeArray} minSearchLength={3} />`}
  bad={`// ❌ Load thousands of records immediately on focus
<Autocomplete options={hugeArray} openOnFocus={true} />`}
/>

<DoAndDont
  good={`// ✅ Provide clear error messages
<Autocomplete error="Please select a valid destination city from the list." />`}
  bad={`// ❌ Leave the user guessing why their input was rejected
<Autocomplete error="Invalid" />`}
/>

<DoAndDont
  good={`// ✅ Use the built-in description extractor

## Autocomplete Accessibility Guide

Autocomplete follows the WAI-ARIA Combobox pattern and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>ArrowDown</KeyboardKey> | Highlights the next option in the list. Skips disabled options. |
| <KeyboardKey>ArrowUp</KeyboardKey> | Highlights the previous option in the list. Skips disabled options. |
| <KeyboardKey>Enter</KeyboardKey> | Selects the currently highlighted option and closes the dropdown. |
| <KeyboardKey>Escape</KeyboardKey> | Closes the dropdown without selecting an option. |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"combobox"` | Always applied to the input element. |
| `role` | `"listbox"` | Always applied to the dropdown container. |
| `role` | `"option"` | Always applied to individual list items. |
| `aria-expanded` | `"true" \| "false"` | Applied to input, reflecting the dropdown's visibility state. |
| `aria-controls` | `string` | Applied to input when dropdown is open, linking to listbox ID. |
| `aria-selected` | `"true" \| "false"` | Applied to the currently highlighted list item via arrow keys. |
| `aria-invalid` | `"true" \| "false"` | Set to true when the `error` prop is provided. |

### Screen Reader Behavior

When the user types, the list filters. The screen reader will announce the state of the combobox. As the user navigates with Up/Down arrows, the screen reader uses `aria-activedescendant` (or focus management) to read out the currently highlighted `role="option"`, including its label and description. When an error is present, `aria-invalid` alerts the user.

### Accessibility Checklist

- [ ] Ensure the `label` prop is always provided (or use `aria-label` via standard HTML props).
- [ ] Do not trap focus inside the dropdown; Escape must always return to standard flow.
- [ ] If fetching async data, ensure `loadingMessage` is descriptive so screen readers can announce it.
- [ ] Always test with keyboard-only navigation before shipping.

## Common Autocomplete Patterns

### Async Server-Side Search

Used when: You are querying an external API based on user input, rather than filtering a static array locally.

<!--
EXAMPLE: Async Server-Side Search
PURPOSE: Demonstrates fetching data dynamically
OUTPUT: Autocomplete that queries an API as you type
USE WHEN: The dataset is too large to load into memory
SOURCE: Common usage pattern for Autocomplete
-->
```tsx
import { useState, useEffect } from 'react';
import { Autocomplete } from '@luxis-ui/core';

export default function AsyncAutocomplete() {
  const [options, setOptions] = useState<any[]>([]);
  const [loading, setLoading] = useState(false);
  const [query, setQuery] = useState('');

  useEffect(() => {
    if (query.length < 2) {
      setOptions([]);
      return;
    }

    const timer = setTimeout(() => {
      setLoading(true);
      // Simulate API call
      fetch(`https://api.example.com/search?q=${query}`)
        .then(res => res.json())
        .then(data => setOptions(data))
        .catch(() => setOptions([]))
        .finally(() => setLoading(false));
    }, 500); // debounce

    return () => clearTimeout(timer);
  }, [query]);

  return (
    <Autocomplete
      label="Async Search"
      placeholder="Type at least 2 chars..."
      options={options}
      loading={loading}
      disableClientFilter={true} // IMPORTANT: Stops React from filtering the API results locally
      onChange={(val) => setQuery(val)}
      onSelect={(val, obj) => console.log('Selected API item:', obj)}
    />
  );
}
```

## Troubleshooting Autocomplete

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Filtering doesn't work for async API responses | Relying on default behavior | Set `disableClientFilter={true}` so the component shows exactly what you pass it. |
| Dropdown shows empty when text doesn't match | Missing labels on data objects | Ensure your array objects have a `label` key, or use `getOptionLabel`. |
| Value isn't registering correctly in `onSelect` | Objects don't have a `value` key | Ensure your objects have a `value` key, or use `getOptionValue`. |
| Click event doesn't fire when using `renderOption` | Forgetting `onClick` in your custom markup | You must attach `onClick={() => handleOptionClick(option)}` (handled internally if you don't override). |

### Frequently Asked Questions

**Q: Can I allow the user to submit text that isn't in the options list?**
A: Autocomplete is designed for selection from a list. You can listen to the `onChange` event to capture free text, but `onSelect` only fires when an actual option is clicked or entered.

**Q: Why does the dropdown close immediately when I click a custom `renderOption`?**
A: When building custom options, ensure you use `onMouseDown={(e) => e.preventDefault()}` on your wrapper. Otherwise, the input's `onBlur` event fires before the click registers, closing the list immediately.

**Q: How do I load options asynchronously only when the user opens the dropdown?**
A: You can attach an `onFocus` handler via native props to trigger your API call when the input receives focus.

**Q: Does it support multi-select?**
A: No, the `Autocomplete` component is strictly for single selection. For multiple selections, use the `MultiSelect` component.
