# Menu

<ComponentStatus status="stable" version="1.0.0" aria="WAI-ARIA Menu Button" />

The Menu system provides a comprehensive set of components for building navigation sidebars, horizontal top bars, and contextual dropdown action menus. It includes built-in support for nested submenus, keyboard navigation, and responsive mobile layouts.

</Callout>

## Before You Start

This package exports three main pieces: `Menu` (the container), `MenuItem` (the individual row), and `ActionMenu` (a wrapper that creates a dropdown triggered by a button). Use `Menu` for persistent navigation and `ActionMenu` for transient context menus.

<Callout type="tip" title="New to Luxis UI?">
  ActionMenu abstracts away the need to manage open/close state manually, unlike some other libraries.
</Callout>

You can replace the default ActionMenu button with any custom component.

export default function CustomTriggerExample() {

This is ideal for user avatars in application headers.

### Controlled ActionMenu (Render Function)

When you need total control over the trigger's state and rendering logic, pass a function as the `trigger` prop.

When to use: When you need the trigger button to reflect the open/closed state visually or handle its own click events.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default ActionMenu manages its own state (uncontrolled). Use the render prop pattern when the trigger component needs access to `isOpen` or `toggle`.
</Callout>

<!--
EXAMPLE: Controlled ActionMenu
PURPOSE: Using a render function for the trigger
OUTPUT: A custom button that changes text based on menu state
USE WHEN: The trigger needs complex internal state logic based on the menu
SOURCE: packages/luxis-ui/src/Menu/ActionMenu.tsx
-->
```tsx
import { ActionMenu } from '@luxis-ui/core';
import { EditIcon } from '@luxis-ui/icons';

export default function RenderPropExample() {
  return (
    <ActionMenu
      items={[
        { label: 'Rename', icon: <EditIcon /> },
        { label: 'Move to folder' }
      ]}
      trigger={({ isOpen, toggle, disabled }) => (
        <button
          onClick={toggle}
          disabled={disabled}
          style={{
            background: isOpen ? '#3b82f6' : '#e5e7eb',
            color: isOpen ? 'white' : 'black',
            padding: '8px 16px',
            border: 'none',
            borderRadius: '4px',
            cursor: 'pointer'
          }}
        >
          {isOpen ? 'Close Options ▲' : 'Open Options ▼'}
        </button>
      )}
    />
  );
}
```

## Menu Best Practices

Follow these guidelines to ensure your menus are intuitive and accessible.

<DoAndDont
  good={`// ✅ Group related actions with dividers
<ActionMenu items={[
  { label: 'Copy' },
  { label: 'Paste' },
  { divider: true },
  { label: 'Delete', variant: 'danger' }
]} />`}
  bad={`// ❌ Don't mix destructive actions with safe ones without visual separation
<ActionMenu items={[
  { label: 'Copy' },
  { label: 'Delete', variant: 'danger' },
  { label: 'Paste' }
]} />`}
/>

<DoAndDont
  good={`// ✅ Use the danger variant for destructive actions
<MenuItem label="Delete Data" variant="danger" />`}
  bad={`// ❌ Don't rely solely on icons to convey destruction
<MenuItem label="Delete Data" icon={<TrashIcon color="red" />} />`}
/>

<DoAndDont
  good={`// ✅ Use ActionMenu for context menus
<ActionMenu triggerLabel="More" items={actions} />`}
  bad={`// ❌ Don't use Menu inside a modal for simple dropdowns
<Modal><Menu items={actions} /></Modal>`}
/>

<DoAndDont
  good={`// ✅ Provide shortcuts for power users
<MenuItem label="Save" shortcut="⌘S" />`}
  bad={`// ❌ Don't use shortcuts for rarely used items

/>

## Menu Accessibility Guide

Menu follows the Menu Button WAI-ARIA pattern and meets WCAG AA standards.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Focuses menu items |
| <KeyboardKey>Enter</KeyboardKey> | Activates item, toggles submenu, or opens ActionMenu |
| <KeyboardKey>Space</KeyboardKey> | Activates item, toggles submenu, or opens ActionMenu |
| <KeyboardKey>ArrowDown</KeyboardKey> | Opens submenu |
| <KeyboardKey>ArrowUp</KeyboardKey> | Closes submenu |
| <KeyboardKey>Escape</KeyboardKey> | Closes ActionMenu or responsive mobile menu |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"menu"` | Applied to the container |
| `role` | `"menuitem"` | Applied to individual items |
| `aria-haspopup` | `"menu"` | When an item has a submenu or on the ActionMenu trigger |
| `aria-expanded` | `boolean` | Indicates if a submenu or ActionMenu is open |
| `aria-disabled` | `"true"` | When an item or menu is disabled |

### Screen Reader Behavior

Screen readers will identify the `ActionMenu` trigger as a button with a menu popup. When opened, it will read the contents as a menu list. `MenuItem` components announce their label, state (e.g., active or disabled), and whether they contain a submenu (collapsible/expandable).

### Accessibility Checklist

- [ ] Ensure `triggerLabel` is meaningful if not using a custom trigger with text.
- [ ] Do not trap focus indefinitely within the menu.
- [ ] Use valid `aria-label` attributes if rendering icon-only custom triggers.
- [ ] Always verify with keyboard-only navigation before shipping

## Menu Design Tokens

<Callout type="tip" title="What are design tokens?">
  Design tokens are CSS custom properties that store design decisions like colors, spacing, and radius. Override them to restyle Menu without fighting CSS specificity.
</Callout>

| Token | Default Value | Description |
|-------|--------------|-------------|
| `--lxs-background-hover` | Dynamic | Background color for hovered menu items |
| `--lxs-background-active` | Dynamic | Background color for active menu items |
| `--lxs-border-color` | Dynamic | Color of menu dividers |
| `--lxs-shadow-sm` | Dynamic | Shadow applied to vertical menus |
| `--lxs-shadow-lg` | Dynamic | Shadow applied to ActionMenu dropdowns |

**Override globally:**
```css
:root {
  --lxs-shadow-lg: 0 10px 15px -3px rgba(0, 0, 0, 0.5);
}
```

**Override for one section:**
```css
.my-dashboard {
  --lxs-background-hover: #e0f2fe;
}
```

## Troubleshooting Menu

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Dropdown goes off-screen | `position="bottom-end"` near right edge | `position="bottom-start"` or adapt based on layout |
| Mobile menu doesn't appear | Missing `<meta name="viewport">` | Ensure standard responsive meta tag is present |
| ActionMenu won't close on click | Missing `onClick` in item | Ensure `onClick: () => {...}` is defined |
| Submenu icons don't align | Mixing items with/without icons | Pass an empty/transparent icon to align text |

### Frequently Asked Questions

**Q: How do I route to a new page using a MenuItem?**
A: Provide an `onClick` handler that calls your router's navigation method (e.g., `router.push('/page')`), or wrap the MenuItem text in a standard Link component if appropriate for your setup.

**Q: Can I keep the ActionMenu open after clicking an item?**
A: By default, `ActionMenu` closes when an item with an `onClick` handler is clicked. To prevent this, you would need to implement a fully custom trigger using the render function pattern and manage the `isOpen` state manually if necessary, though this goes against typical dropdown UX.

**Q: How do I change the width of the ActionMenu dropdown?**
A: Use standard CSS targeting the class passed to `className` on the `ActionMenu`, e.g., `.my-menu { width: 300px; }`.

**Q: Does Menu support dark mode?**
A: Yes. All Menu components listen for the `data-theme="dark"` attribute on the document root and adjust their colors, borders, and hover states automatically.
