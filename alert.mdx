### Controlled Alert

When to use: When a parent component needs to read or drive the state.

<Callout type="info" title="Controlled vs Uncontrolled">
  By default Alert manages its own state (uncontrolled).
  Use the controlled pattern when syncing with a URL param, form
  library, or another component.
</Callout>

<!--
EXAMPLE: Controlled
PURPOSE: useState-driven Alert with external state management
OUTPUT: Alert whose state is owned by the parent
USE WHEN: Programmatically reading or setting component state
SOURCE: Derived from Alert.tsx controlled/uncontrolled pattern
-->
```tsx
import { useState } from 'react';
import { Alert } from '@luxis-ui/core';

export default function ControlledExample() {
  const [isVisible, setIsVisible] = useState(true);

  if (!isVisible) {
    return (
      <button onClick={() => setIsVisible(true)} style={{ padding: '8px 16px' }}>
        Show Alert Again
      </button>
    );
  }

  return (
    <Alert
      title="Controlled Alert"
      description="This alert's visibility is tied to the parent state."
      dismissible={true}
      onClose={() => setIsVisible(false)}
    />
  );
}
```

## Alert Best Practices

Effective alerts use appropriate severity variants and concise messaging.

<DoAndDont
  good={`// ✅ Match variant to severity
<Alert variant="error" title="Payment Failed" />`}
  bad={`// ❌ Use info for critical failures
<Alert variant="info" title="Payment Failed" />`}
/>

<DoAndDont
  good={`// ✅ Keep messages brief and actionable
<Alert title="File uploaded" description="Your document has been processed." />`}
  bad={`// ❌ Write long paragraphs inside alerts
<Alert title="Upload status" description="We received your file at 10:45 AM. It was processed through our system and scanned for viruses. No viruses were found. The file is now available in your dashboard." />`}
/>

<DoAndDont
  good={`// ✅ Provide an action for resolutions
<Alert variant="warning" title="Storage full" action={<Button>Upgrade</Button>} />`}
  bad={`// ❌ Describe the action but offer no link
<Alert variant="warning" title="Storage full" description="Go to the settings page, click billing, and upgrade your plan." />`}
/>

<DoAndDont
  good={`// ✅ Use the title prop for quick scanning
<Alert title="Network Error" description="Reconnecting..." />`}
  bad={`// ❌ Put everything in the description
<Alert description="Network Error: Reconnecting..." />`}
/>

Alert forwards rest props to its underlying `<div>`, so
all standard HTML div attributes are also accepted.

| Prop | Description | Example Value |

## Alert Accessibility Guide

Alert follows the WAI-ARIA alert pattern and meets WCAG AA.

### Keyboard Shortcuts

| Key | Action |
|-----|--------|
| <KeyboardKey>Tab</KeyboardKey> | Moves focus to the action button or the close button inside the alert. |
| <KeyboardKey>Enter</KeyboardKey> | Triggers the close button if focused. |

### ARIA Attributes

| Attribute | Value | When |
|-----------|-------|------|
| `role` | `"alert"` | Always applied to the outer wrapper container. |
| `aria-label` | `"Close alert"` | Always applied to the dismiss button when present. |

### Screen Reader Behavior

Because the component uses `role="alert"`, when an alert renders dynamically on the page, the screen reader will interrupt its current announcement and immediately read the text inside the alert. It reads the title and then the description.

### Accessibility Checklist

- [ ] Do not use `role="alert"` for non-critical information that doesn't require immediate interruption. Override the role prop to `status` for polite announcements.
- [ ] If using custom icons, ensure they are purely decorative or their meaning is described in the text.
- [ ] Ensure any interactive elements inside the `action` prop have accessible labels.
- [ ] Always test with keyboard-only navigation before shipping.

### Offline Status Indicator

Used when: The application loses network connectivity.

<!--
EXAMPLE: Offline Status Indicator
PURPOSE: Notifying users of network loss
OUTPUT: Warning alert fixed to the top or inline
USE WHEN: Building PWAs or robust web apps
SOURCE: Common usage pattern for Alert
-->
```tsx
import { Alert } from '@luxis-ui/core';
import { useState, useEffect } from 'react';

export default function OfflineAlert() {
  const [isOffline, setIsOffline] = useState(false);

  useEffect(() => {
    const handleOffline = () => setIsOffline(true);
    const handleOnline = () => setIsOffline(false);

    window.addEventListener('offline', handleOffline);
    window.addEventListener('online', handleOnline);

    return () => {
      window.removeEventListener('offline', handleOffline);
      window.removeEventListener('online', handleOnline);
    };
  }, []);

  if (!isOffline) return null;

  return (
    <Alert
      variant="warning"
      alertStyle="left-accent"
      fullWidth={true}
      title="You are offline"
      description="Changes made will be synced when your connection is restored."
    />
  );
}
```

## Troubleshooting Alert

### Common Mistakes

| Symptom | Wrong ❌ | Right ✅ |
|---------|---------|---------|
| Alert doesn't show up after clicking close | Trying to control it externally without reading state | It manages state internally; remount with a key if you need it back. |
| Icons are blurry or misaligned | Passing text instead of SVG nodes to `icon` | `icon={<CheckCircleIcon />}` |
| Screen reader says nothing | Overriding `role` to empty string | Leave `role="alert"` (the default) for immediate announcements. |
| Action button looks strange | Expecting the Alert to style your custom button | Style the button passed to `action` explicitly. |

### Frequently Asked Questions

**Q: Can I restore a dismissed alert?**
A: Because the component hides itself using internal state when dismissed, you must either unmount and remount it using a React `key`, or control it fully from the parent instead of relying on the built-in `dismissible` behavior.

**Q: Does it use a Portal to render on top of everything?**
A: No, the Alert renders exactly where you place it in the DOM flow. If you want a floating notification, use the `Toast` component instead.

**Q: How do I change the default icon to my own SVG?**
A: Pass your custom SVG element directly to the `icon` prop.

**Q: Can I put a link in the description?**
A: Yes! Use the `children` prop instead of `description` to pass a full React fragment containing links or other HTML.
